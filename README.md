# Beyond: Craftlines / 超越维度：合成链

[English](README_EN.md) | **简体中文**

面向 Beyond Dimensions 的配方驱动自动合成系统。Beyond: Craftlines 将 JEI 中的配方展开为可交互的递归合成树，从 BD 网络统一预留原料、调度工作台与真实机器、回收产物，并以可追踪、可取消、可持久化的订单完成从“查到配方”到“拿到成品”的整条生产链。

## 核心功能

- **从 JEI 直接下单**：从配方页面打开 Craftlines 会立即进入订单页面。第一阶段按配置的每 tick 条目上限建立并缓存配方查找索引，完成后一次性显示完整树；第二阶段保持树形布局不变并继续准备规划目录。两级缓存仅在配方重载后失效，重复打开无需重新索引。根配方始终保持为入口所选配方，后续层级可以自动规划，也可以手动切换。
- **清晰的合成树与原料统计**：EMI 风格的自上而下树形界面会合并同层重复材料，提供配方预览、候选原料选择、缺料高亮，以及理论用量、实际网络提取量和余料视图。
- **由服务端验证的可靠规划**：客户端基于服务端签发的版本化库存快照进行快速搜索，服务端在下单前重新校验完整方案；库存或配方状态发生变化时会拒绝过期计划，避免幽灵材料和错误扣料。
- **Beyond Dimensions 网络执行**：订单直接从对应 BD 网络预留和提取资源，支持正 `long` 数量；同一网络按 FIFO 串行提交，机器拒收的余量会安全退回网络。
- **订单内并行调度**：同一订单中依赖已经满足的配方步骤可同时推进；不同机器可以并行工作，同一维度坐标上的机器仍严格互斥。
- **真实配方与容器语义**：工作台步骤调用服务端原始配方逻辑，保留动态组件、耐久工具、容器返还物以及模组自定义的 `assemble` 和剩余物行为。
- **配方机器自动化**：使用网络联结器绑定或解绑原版及第三方机器；BD 网络组件除外。Craftlines 根据 JEI 催化剂与服务端 `RecipeType` 建立确定性映射，并通过机器真实能力投料、检测产出和执行回滚，不依赖针对特定科技模组的硬编码分支。
- **原生网络熔炉支持**：Beyond Dimensions 的网络熔炉、网络高炉和网络烟熏炉无需手动绑定；Craftlines 会在同一网络中寻找空闲设备，投送输入并等待真实产物返回网络。
- **可控的批次调度**：AE2 风格阻挡模式会等待上一批完成并回收后再发送下一批，适用于容易串配方或内部仍有残留输入的机器。
- **合成链供给器**：供给器可按所绑定机器支持的配方类型接收订单产物，并允许外部管道提取；配置界面、目标图标和 Jade 信息让产线用途在世界中保持可见。
- **持久化订单与状态管理**：订单、步骤进度和机器绑定会随世界保存；玩家可以查看网络订单、诊断等待原因并取消尚未完成的任务。

## 支持版本

- Minecraft 1.20.1 / Forge 47 / Java 17
- Minecraft 1.21.1 / NeoForge 21.1 / Java 21
- Minecraft 26.1.2 / NeoForge 26.1.2 / Java 25

除非明确限定版本，功能说明和开发改动均适用于以上三个版本。

- `mod_id`: `beyond_craftlines`
- 必需依赖：Beyond Dimensions、JEI

本模组只负责下单系统：JEI 配方页入口、EMI 风格递归配方树、AE2/RS 风格订单确认、BD 网络扣料与合成、原版及第三方机器配方类型绑定、订单持久化/状态/取消，以及可配置配方类型的合成链供给器。

构象捕获、沙盒试产、报告、稳态产线与图纸复制已经迁移到独立模组 `Sky Logistics: Linefold`，本模组不再注册任何构象方块、物品、命令、维度或 SavedData。

## 构建

未明确限定版本时，改动、验证与打包均同时覆盖三个支持版本。分别使用 Java 17、21、25 执行：

```bash
# Minecraft 1.20.1 / Forge
cd versions/1.20.1 && ../../gradlew --no-daemon build

# Minecraft 1.21.1 / NeoForge（从项目根目录执行）
cd ../.. && ./gradlew --no-daemon build

# Minecraft 26.1.2 / NeoForge
cd versions/26.1.2 && ../../gradlew --no-daemon build
```

三个产物分别位于：

- `versions/1.20.1/build/libs/beyond_craftlines-0.1.3+1.20.1.jar`
- `build/libs/beyond_craftlines-0.1.2+1.21.1.jar`
- `versions/26.1.2/build/libs/beyond_craftlines-0.1.2+26.1.2.jar`

## 使用概要

1. 在 JEI 配方查询页点击 Craftlines 入口，确认递归配方树与数量后下单；根节点固定使用入口所在的那一条 JEI 配方，自动规划和手动切换只影响后续层级。树采用 EMI 风格的自上而下布局，目标产物在上、原料逐层向下展开，同一配方层内的相同物品会合并并累计数量；默认只完整显示同一组件资源键最靠近树根的一次，后续更深层位置显示可点击跳转引用，此显示折叠可由客户端配置关闭。悬浮可查看所选配方的原料 → 产物图形预览、配方族和 ID。右侧原料汇总采用 EMI 风格的图标网格与数量叠字，可切换理论总计、实际网络提取和余料；规划缺料时立即改为红色缺料网格。点击 tag/OR ingredient 节点会打开完整候选物品网格供直接选择，右击下级节点可切换生产配方，按住 Ctrl 右击可恢复自动选择。玩家已保存的配方与原料偏好优先于自动建议；客户端优化预算按唯一物品 ID 计数，预算耗尽只停止继续寻找更优候选，不会使已经完整可制造的方案失效。
2. 网络联结器右击原版或第三方机器进行绑定，潜行右击解绑；BD 网络熔炉等 BD 网络组件不可绑定。配方类型来自 JEI 正式催化剂 category UID 与服务端同 ID `RecipeType` 的确定性映射。对于把原版 `Recipe#getIngredients()` 留空的机器配方，Craftlines 会从其公开的 input representations 读取物品、流体及已注册化学品等 BD 资源，并在服务端重新校验、预留和投送。
3. 外部机器按真实能力投料和收取产物，不内置 Mekanism 或其他具体模组分支。
4. BD 网络熔炉、网络高炉和网络烟熏炉无需绑定；订单直接向同网络的空闲对应炉型投料，并等待真实产物回网。
5. 同一 BD 网络的订单由 Craftlines 按 FIFO 串行取得库存事务权；取得执行权的订单会并行推进所有依赖已满足的步骤。不同机器可同时加工，同一机器一次只分派一个步骤，机器拒收的余量自动退回网络。
6. 下单时可开启 AE2 风格阻挡模式：每次只推送一次配方输入，上一批完成并回收后才发送下一批；目标机器预存本配方输入时也会等待。
7. 合成链供给器只接受订单产生的资源，不能由管道写入；右击可随时打开配置界面，但只有先用网络联结器选择供给器并扫描目标机器后，界面才会列出可勾选的配方类型，不支持手工填写；若供给器总共只有一个候选且尚未配置，该候选会在绑定完成时自动选中并立即启用。扫描成功后，供给器四个水平侧面中央会显示最近目标方块的 Jade 风格 8×8 对应物品图标。库存可由外部管道提取。
8. 工作台配方统一通过服务端原配方模拟，保留动态组件、耐久工具、容器返还物和模组自定义 `assemble/getRemainingItems` 行为。相同 BD 组件键的稳定输入会按可用数量一次批量结算；会改变耐久或组件的工具才逐次推进。订单数量使用正 `long`，最大支持 `Long.MAX_VALUE`。
9. 配方候选搜索使用服务端签发的版本化库存快照在客户端后台完成；服务端对完整建议做固定分支线性复算，库存或配方版本变化时拒绝下单。
