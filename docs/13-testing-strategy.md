## 4. 游戏内验收清单（最终态）

1. 打开 BD 维度网络界面后 JEI 才出现下单按钮；中键网络物品可进入配方树；未打开网络界面时无按钮。
1b. 预览 EMI 风格配方树并下单执行成功；稳态构象图不会作为配方来源出现。
2. 验证 BD 三种网络炉无法被联结器绑定，但烧炼三族仍可直接下单。
2a. 分别用网络熔炉、网络高炉、网络烟熏炉下单：确认原料进入真实输入槽、遵守燃料与加工时间，并在“收入网络”开启或关闭时都能把本订单产物计入网络。
2b. 同一 BD 网络连续提交两个订单，确认第二单等待第一单事务结束；不同网络的订单可以各自推进。
2c. 清空目标机器，开启阻挡模式并下单 2 个产物，确认每次只投入一批配方原料，首批产物完成并回收前不投入第二批；关闭阻挡模式时应按机器剩余容量投料。另保留 AE2 的预存配方输入阻止首批推送语义。
3. 框选含天穹节点的小型产线，测试维生成原版屏障围挡。
3b. 观察者离开范围 5 秒自动退出并还原模式。
4. 原维向测试维送料，报告出现对应输入；产物跨回原维计入输出。
5. 确认编译，驱动器自动跑至少 3 个周期。
6. 复制台扣 CAPEX 复制图纸。
7. 直接绑定第三方机器后，订单从 BD 网络自动投料，机器产物自动返回网络；解绑后该配方族不可调度。
8. `/beyond_craftlines cancel` 可取消合成链并退料。
9. 分别验证带容器返还物、会损耗但不立即消耗的工具、复制输入组件到产物的升级配方；连续两次合成必须使用第一轮返还的实际物品状态。
10. 输入 `2147483648` 以上的订单数量仍能下单和持久化；用接近 `Long.MAX_VALUE` 的复杂多层配方预览时不得出现负需求、崩溃或 `ArithmeticException`。

### 4.1 Mekanism 冶金灌注机人工绑定用例

前置：安装 JEI 与 Mekanism 1.21.x，并确保服务端和客户端模组集合一致。

1. 加入或管理一个 BD 网络，放置 Mekanism 冶金灌注机；无需放置合成链供给器。
2. 手持网络联结器对世界中的冶金灌注机方块普通右击，必须消费本次交互且不得打开机器自身 GUI，并确认出现黑蓝绑定边框；潜行右击应解绑且同样不得打开 GUI。
3. 预期成功消息中的配方族为 `mekanism:metallurgic_infusing`；JEI category UID 也应为该值，机器方块/物品 ID 则是 `mekanism:metallurgic_infuser`。
4. 把目标换成熔炉并伪装/复用该 category 时，服务端催化剂校验必须拒绝绑定。
5. 重启服务端后，绑定记录中的 `jei_types` 与 `families` 均应保留 `mekanism:metallurgic_infusing`。

本用例只验收通用的“JEI 催化剂 → category → 同 ID 服务端 RecipeType”链路；生产代码、自动测试、映射表和本地化文本不得包含 Mekanism ID 或 Chemical 名称。冶金灌注配方中未被通用资源模型覆盖的 Chemical 必须由机器自身或玩家预先满足；Craftlines 只调度已识别的物品输入、通用等待机器产出，不得声称已供应或能诊断具体 Chemical。
