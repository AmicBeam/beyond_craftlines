# Beyond: Craftlines 验收文档

本文用于验收合成链供给器的配方类型确认 GUI。案例使用 Create 工作盆，因为同一个
`create:basin` 催化剂通常会被 JEI 同时登记到以下配方类型：

- `create:mixing`：搅拌；
- `create:packing`：压块，对应服务端 `create:compacting` 配方族。

界面显示文本会随机器模组/JEI 语言包变化，验收时以 JEI 当前登记结果为准。三个支持版本
都必须执行本验收；若对应版本提供 Create 工作盆，则预期至少出现“搅拌”和“压块”两项，
否则应选择一个在 JEI 中登记到至少两个配方类型的机器作为等价案例。

## 1. 验收环境

| Minecraft | 加载器 | Java | Beyond Dimensions / JEI |
| --- | --- | ---: | --- |
| 1.20.1 | Forge 47 | 17 | 使用 `versions/1.20.1/gradle.properties` 声明的版本 |
| 1.21.1 | NeoForge 21.1 | 21 | 使用根目录 `gradle.properties` 声明的版本 |
| 26.1.2 | NeoForge 26.1.2 | 25 | 使用 `versions/26.1.2/gradle.properties` 声明的版本 |

每行都使用当前待验收的 Beyond: Craftlines 构建。机器模组应选择该 Minecraft 版本可用且
能让同一催化剂对应至少两个 JEI 配方类型的版本。

建议新建测试世界并开启作弊。验收玩家需要先连接一个 Beyond Dimensions 网络，并拥有该网络的管理员权限。

准备以下物品：

- 合成链供给器；
- 网络连接器；
- Create 工作盆；
- Jade（用于检查最终启用类型，可选但推荐）。

## 2. 基础布置

1. 确认当前玩家已连接到一个自己可管理的 Beyond Dimensions 网络。
2. 放置合成链供给器，确认它已绑定到当前网络。
3. 在附近放置一个 Create 工作盆。
4. 确认 JEI 中工作盆被登记为搅拌和压块配方的催化剂。

预期结果：供给器和工作盆均保持加载，供给器可正常识别当前网络；此时尚未扫描工作盆。

## 3. GUI 默认可打开，未扫描时提供手动兜底

1. 不使用网络连接器，普通右击合成链供给器。
2. 观察供给器 GUI。

预期结果：

- GUI 正常打开，不要求先完成工具绑定；
- 界面显示配方类型搜索框；聚焦或输入时展开下拉列表，最多显示五行并支持滚轮滚动；
- 搜索同时匹配 JEI 本地化分类名和 `namespace:path` UID，悬停项使用天穹物流标签过滤列表风格的青色高亮；
- 下拉框严格单选，只能选择一个父配方类型，不能累计多个父类型；
- 选择后服务端验证该类型能解析到当前已加载配方族，验证成功后重新打开配置界面；
- 重新打开的界面固定显示所选父类型，并展示该类型可用的子标签/材料组供玩家继续配置。
- 供给器侧面在没有目标方块图标时显示该父类型的 JEI 本地化名称；标题不可用时显示 UID。

## 4. 使用工作盆生成候选选项

1. 关闭供给器 GUI。
2. 手持网络连接器，潜行右击合成链供给器。
3. 确认出现“已选择此合成链供给器”的提示。
4. 使用同一个网络连接器普通右击 Create 工作盆。
5. 确认出现“已将识别到的配方类型加入供给器候选项”的提示。
6. 普通右击供给器，重新打开 GUI。

预期结果：

- GUI 中出现工作盆经 JEI 识别得到的候选类型；
- Create 6.0.9 标准环境中至少包含“搅拌”和“压块”，对应 UID 分别为
  `create:mixing` 和 `create:packing`；后者必须解析为服务端 `create:compacting` 配方族；
- 新出现的候选项默认未启用，扫描动作本身不会自动让供给器承接这些配方；
- 已存在扫描候选时不显示手动下拉，仍只能操作扫描候选。

如果没有出现扫描选项，先在 JEI 中确认工作盆确实是对应 category 的正式催化剂，再检查 JEI
运行时索引是否已经初始化；候选为空时可使用单选手动兜底，但仍必须通过服务端配方族校验。

### 4.1 单候选自动启用

1. 使用一个候选为空、尚未配置的供给器。
2. 选择该供给器后，扫描一个只对应单个 JEI 配方类型的机器，例如仅识别出粉碎配方的 Mekanism 粉碎机。
3. 不打开供给器 GUI，直接查看绑定反馈与 Jade。
4. 再打开供给器 GUI 核对选项。

预期结果：

- 绑定反馈明确提示唯一候选已自动选中并启用；
- 无需进入 GUI 点击一次，该配方族已经能被规划器使用；
- Jade 立即显示这一条已启用类型；
- GUI 打开后该唯一候选已经勾选；
- 若供给器后来累计为多个候选，不自动替玩家启用新增候选。

### 4.2 拒绝非 JEI 催化剂的储物设备

1. 放置一个具有物品或其他已注册储物能力、但未被 JEI 登记为任何配方分类催化剂的方块。
2. 不选择供给器，手持网络连接器普通右击该方块，尝试直接绑定。
3. 选择供给器后再次右击该方块，尝试把它加入供给器候选。

预期结果：

- 两次操作都明确提示“设备 `<namespace:block_id>` 未在 JEI 中注册为任何配方催化剂”，其中 ID 必须是当前目标方块的实际注册 ID，且提示中不出现空的分类列表或多余占位标点；
- 该方块不会因为拥有储物能力而创建直接机器绑定，也不会加入供给器候选；
- JEI 正式登记为催化剂且具备可自动化能力的设备仍可正常绑定。

## 5. 手动确认单个配方类型

1. 在供给器 GUI 中只勾选“搅拌”。
2. 保持“压块”未勾选。
3. 关闭并再次打开供给器 GUI。
4. 使用 Jade 查看供给器提示。

预期结果：

- 再次打开 GUI 后，“搅拌”保持勾选，“压块”保持未勾选；
- Jade 只显示已启用的“搅拌”，不显示仅作为候选存在的“压块”；
- Craftlines 将该供给器视为 `create:mixing` 的可用供给端点；
- Craftlines 不会将该供给器视为 JEI `create:packing`（服务端 `create:compacting`）的可用供给端点。

## 6. 手动确认多个配方类型

1. 再次打开供给器 GUI。
2. 同时勾选“搅拌”和“压块”。
3. 关闭并重新打开 GUI。
4. 使用 Jade 查看供给器提示。

预期结果：

- 两个选项均保持勾选；
- Jade 同时显示“搅拌”和“压块”；
- 供给器可同时作为 JEI `create:mixing` 和 `create:packing` 的供给端点，后者承接
  `create:compacting` 配方族。

## 6.1 多材料组筛选

使用会公开多个逻辑输入部分的配方类型，例如 `goety:ritual` 的普通材料与激活物品：

1. 扫描对应机器并在供给器 GUI 中勾选该配方类型。
2. 确认主按钮下方出现一组宽度更窄的材料组按钮，初始均未勾选。
3. 保持全部材料组未勾选并提交一次订单。
4. 只勾选“激活物品”，再次提交订单。
5. 在另一个供给器上只勾选“材料”，并让两个供给器共同完成一次订单。
6. 取消“激活物品”，使其再次回到全部未勾选。

预期结果：

- 二级按钮支持多选，关闭并重新打开 GUI 后保持选择；
- 全部未选表示接受所有材料组，不会导致该供给器拒绝全部材料；
- 选择任意组后切换为白名单，只向该供给器投送被选组；
- 不同材料组可同时投送到不同供给器，产物返回前所有参与供给器保持占用；
- 取消最后一个二级选项后恢复接受全部；
- 只有一个逻辑材料组的配方类型不显示二级按钮，行为与旧版本一致。

## 6.2 Malum 精魂与网络入口偏好

1. 为同一产物保存一个非首位配方偏好。
2. 确认 Minecraft「按键控制」的 Beyond: Craftlines 分类中存在“下单悬浮资源”（默认中键），在 BD 网络物品槽悬浮该产物并按此键，等待订单树完成规划。
3. 分别在 JEI 配方槽、物品列表和书签列表悬浮该产物并按同一按键；将其临时重绑为键盘键后重复验证。
4. 从 JEI 的另一条具体配方点击 Craftlines 按钮打开同一产物。
5. 打开 Malum `spirit_infusion` 配方，例如神圣金锭。
6. 分别打开已有偏好的配方候选页和 Tag/OR 原料候选页，点击右上角“遗忘偏好”。

预期结果：

- 网络按键入口使用已保存偏好，没有有效偏好时才使用首个可用配方；
- 三个 JEI 按键入口均打开同一产物的订单树，使用与网络按键入口一致的配方偏好；
- JEI 入口的自动规划仍保持被点击的具体配方，不被根节点偏好自动替换；玩家在本次合成树中显式手动切换根配方后，按手动选择重新规划；
- 没有已保存偏好时候选页不显示“遗忘偏好”；存在偏好时按钮出现，点击后删除对应客户端持久偏好和本次覆盖、关闭候选页并恢复自动选择；
- Ctrl 右击和 Ctrl+Shift 右击不再承担清除配方或原料偏好的语义；
- Malum 1.20.1 的 `SpiritWithCount#getStacks()` 和 1.21.1 的 record `SpiritIngredient#getItems()`
  均展开为带正确数量的精魂碎片输入；
- 缺料汇总列出真实缺失的金锭、石英或精魂碎片，不把目标产物本身误报为原料。

## 6.3 递归 JEI 候选上传

1. 选择至少三层、每层存在多个 JEI 配方候选的产物。
2. 在树中分别保留自动候选和手动替换一个递归子配方。
3. 提交预览，确认只上传实际选中的虚拟配方描述，而不是整个 JEI 目录。
4. 修改一个上传描述的 family、输入数量或确定性 ID，确认服务端拒绝固定链。

预期结果：

- 每个递归节点的输入、数量与子标签均来自对应 JEI 布局；
- 服务端不查询 RecipeManager 或 recipe IO profile 来补全递归节点；
- 上传按 8 条描述分页并受 64 页、32 槽、每槽 64 候选限制；
- 自动和手动候选均能通过固定链线性复算，篡改描述不能进入订单。

## 6.4 JEI 类型一次性预热

1. 进入世界后等待主网络已启用配方类型的后台预热完成，首次打开其中一种类型的配方树。
2. 关闭后再次打开相同目标和同类型的另一个目标。
3. 再启用一种此前未使用的机器类型并首次打开其配方树，随后重新打开第一种类型。

预期结果：

- 同一 JEI runtime 生命周期内，每个 category 最多完整物化一次；
- 第二次打开相同类型不再显示“正在索引配方”或重新创建该类型的 drawable；
- 新类型只追加自身的虚拟描述，不清空已完成的原生配方索引和规划目录缓存；
- 配方数据包重载、JEI runtime 重建或退出世界后才允许重新预热。

## 7. 取消已启用类型

1. 在 GUI 中取消勾选“搅拌”，只保留“压块”。
2. 重新打开 GUI，并使用 Jade 检查。
3. 再取消所有勾选。

预期结果：

- 第一次修改后只有“压块”生效，“搅拌”仍保留为可再次勾选的候选项；
- 全部取消后，供给器不再承接任何配方类型；
- 已扫描候选仍显示在 GUI 中，玩家可再次勾选，不需要重复扫描。

## 8. 纯 JEI-only 类型与 slot 子标签

执行以下检查：

1. 使用候选为空且尚未配置的供给器，在搜索框输入名称或 UID 片段并选择一个有效类型。
2. 确认界面重新打开后出现该父类型及其可用子标签。
3. 选择 JEI UID 与服务端 `RecipeType` 不同名的分类，确认仍以 JEI UID 保存并下单。
4. 在尚未从该分类下过单时，打开包含 `catalyst` 与 `input_0`/`input_1` slot name 的 JEI 分类对应供给器，确认客户端按帧预算完成该分类布局物化后打开配置，并直接显示 `catalyst` 与 `ingredients` 子标签；随后下单确认虚拟配方沿用相同标签。
5. 使用两个 JEI 子分类共享同一个服务端 `RecipeType` 的配方，确认两个 JEI UID 仍是互相隔离的运行时 family。
6. 使用包含 2、4、5、8、16 个 slot 子标签的分类，分别从供给器和已绑定设备打开配置 GUI，确认子标签按实际数量换行且每行不超过 4 个；父类型、子标签与底部控件互不重叠，翻页后点击命中正确。
7. 绑定 Ars Nouveau 附魔装置，确认只显示 `reagent`（中心素材）与 `pedestal_items`（基座素材），同为中央 X 坐标的顶部基座素材不得混入中心素材。
8. 绑定 Malum 精魂灌注，确认只显示 `spirits`（精魂）、`extra_items`（旁路素材）与 `input`（中心素材），不得出现 `input_left`、`input_center`、`input_right` 或 `input_column_N`。

预期结果：

- 只有候选为空且尚未配置的供给器显示搜索下拉；
- 手动模式只接受一个父类型，批量提交两个或更多父类型被服务端拒绝；
- 有效父类型保存后成为该供给器唯一候选，并可继续配置其子标签；
- 空白供给器的手动模式只允许保存一个 JEI UID；全部分类统一走 JEI-only 临时配方；
- 不加载 `recipe_type_aliases`、`jei_only_recipe_types` 或服务端 RecipeType 验证配置；
- 子标签来自 JEI slot name，并随虚拟输入协议传到服务端；
- 上游未命名但具有显式 `jei_input_group_profiles` 的分类按配方 public 字段/accessor 的输入段数量生成稳定语义标签，数量不匹配时整体回退而不按坐标猜测；
- 子标签每行最多显示 4 个，超过后动态增加行数；当前页空间不足时父类型列表动态分页；
- 普通能力式机器可直接绑定 JEI-only 分类，并以分类 UID 作为兼容配方族接受虚拟配方投料和产物抽取；铁砧、酿造台、堆肥桶、锻造台和切石机仍只能作为供给器目标；
- 原配置不会因非法提交而改变。

## 8.1 EMI、耐久工具与厨锅容器

1. 在 1.20.1 Forge 与 1.21.1 NeoForge 同时安装 JEI、EMI，确认 JEMI 配方页及可映射回 JEI 的 EMI 原版工作台配方页右侧显示 12×12 的 Craftlines 连接器按钮；背景直接使用 EMI `buttons.png` 的空白按钮单元，按钮不与填充、配方树、默认配方按钮重叠，点击后应立即打开页面并在索引就绪后固定当前配方。EMI-only 且无法映射回 JEI 的配方不得显示按钮。
2. 分别在 EMI 物品索引、收藏栏和配方槽悬浮物品并按统一的“下单悬浮资源”键，确认打开未固定根配方的 Craftlines 页面；普通容器槽不得被 EMI hover 路径误判。
3. 在 Craftlines 配方候选页选择配方，确认 EMI BoM 立即使用同一偏好；点击“遗忘偏好”后确认 EMI 同步取消。随后直接在 EMI 设置及取消默认配方，重新打开 Craftlines，确认其客户端持久偏好分别同步为该配方及清除。JEMI 包装 ID、多输出配方和组件不同的同物品输出不得串选。
4. 在 EMI 完成重载后，用网络连接器绑定一个 JEI 催化剂机器，确认 Craftlines 会合并 EMI/JEMI 的工作站元数据，不会误报“未在 JEI 中注册”；供给器、绑定设备和配方树中的分类标题均使用当前游戏语言，多输入组配方的语义子标签仍会显示。
5. 在 26.1.2 仅安装 JEI，确认可选 EMI 桥不影响可配置下单键、JEI 按钮、登录和退出；不得把该版本描述为已支持 EMI。
6. 使用 Farmer's Delight 砧板一次请求超过一把工具耐久的产量，确认树和缺料只要求 `ceil(制作次数 / 单把剩余可用次数)` 把工具，不再按制作次数逐把消耗；供给器配置显示 `tool`/“耐久工具”组。
7. 使用 Farmer's Delight 厨锅的碗装料理，请求多份产物，确认每份碗进入 `container`/“盛装容器”组并投往厨锅容器能力，普通食材不混入该组。
8. 对水桶、奶桶或其他具有空桶 remainder 的工作台配方，确认默认树显示流体候选；在 ingredient 选择器中点选桶物品后重新规划，确认树、缺料和服务端执行均使用桶；遗忘偏好后恢复流体优先。网络无流体但存在桶时，自动规划必须选择桶而不是报缺少流体。
9. 以雕纹石英块链路验证循环恢复：即使先遇到“雕纹石英块 → 石英台阶 → 雕纹石英块”的候选，也必须继续尝试石英块/下界石英路径；对首个 tag 成员自环、后续成员可制造的测试配方做相同验证。
10. 使用原版酿造或其他同一物品 ID、不同 NBT/Data Components 的药水配方，确认候选选择、树节点、右侧缺料、服务端复算和真实投料始终保持同一种药水；旧的仅物品 ID 偏好仍可回退，但新保存的选择必须是组件精确的。

预期结果：EMI 增加配方页按钮、悬停下单入口和双向偏好同步，但不产生新的执行配方类型；耐久与容器语义进入虚拟配方 ID、网络协议、客户端规划、服务端复算和树数量，三处结果一致。

## 10.1 自增配方

1. 在网络中放入 1 个可复制的原版锻造模板，并保证复制配方的其它原料足够。
2. 打开配方树并下单 10 个该模板，分别在阻挡模式开启和关闭时执行。
3. 移走模板种子后重新预览并尝试下单。
4. 对一个非工作台、产物同时也是输入且净产出为正的第三方机器配方重复以上步骤。

预期结果：

- 模板下级显示橙色 `*` 自增节点和最小取用数量 1，不显示紫色跳转或红色循环；
- 其它复制原料按 10 次配方展开，服务端只预留 1 个模板种子；
- 种子不存在时树继续显示数量 1 的缺料节点，服务端拒绝创建订单；
- 真实机器在两种阻挡模式设置下都逐轮投料并等待产物回收，完成后网络净增加 10 个目标且保留 1 个种子；
- 普通非自增配方仍保持原有批量调度行为。

## 11. 清空与库存回归

1. 手持网络连接器，潜行右击供给器以重新选择它。
2. 对空气使用网络连接器。
3. 打开供给器 GUI。
4. 供给器为空时观察右下角的“全部送回网络”按钮。
5. 向供给器写入一批订单资源，保持 GUI 打开并观察按钮状态。
6. 点击“全部送回网络”。
7. 分别在网络容量充足和容量不足的情况下重复测试。

预期结果：

- 对空气使用连接器后，候选和已启用类型全部清空；
- GUI 仍可正常打开，但恢复为无选项状态；
- Jade 显示供给器未绑定配方；
- 供给器为空时“全部送回网络”不可点击，出现资源后无需重新打开 GUI 即可点击；
- 网络容量充足时供给器内容全部回到当前 BD 网络，按钮恢复为不可点击；
- 网络容量不足时只送回网络能够接收的数量，剩余资源原样保留在供给器中，按钮保持可点击；
- 外部管道仍可提取，但玩家和管道仍不能向供给器写入资源。

## 11.1 无线设备连接

1. 先使用未启用任何配方类型的供给器，手持连接器普通右击；再为它启用至少一种配方类型并重复操作。
2. 观察供给器高亮，再依次右击两台可接收资源设备的指定面。
3. 对其中一台改点另一面，再点击同一个面。
4. 手持连接器左击供给器，并检查 GUI 倒数第三行与 Jade。
5. 向供给器交付设备能够接收的订单资源，依次用“已连接设备”行右侧的单个按钮切换轮询、最近优先和最远优先，观察投送顺序和绑定面限制。
6. 让当前策略的首选目标拒收一种资源，同时让后续目标能够接收它。
7. 将 `provisioner.maxWirelessConnections` 设为 1 并重启服务端，尝试连接第二台设备。
8. 清空供给器所有已启用配方类型。

预期结果：

- 未启用配方类型时不进入无线连接模式，并明确提示先启用至少一种承接配方，不误报网络绑定或管理权限问题；
- 普通右击进入无线连接模式，不要求选择供给器的面；潜行右击仍进入配方候选扫描模式；
- 所选供给器、已连接面和准星指向的候选面均高亮；
- 同一设备换面会更新且不增加数量，再点当前面会断开；
- 左击不破坏方块并打开配置 GUI，GUI 与 Jade 的连接数实时一致；
- 资源只从记录的目标面插入，按钮按轮询 → 最近优先 → 最远优先循环，关闭并重开 GUI 或重启后保持选择；
- 首选目标拒收当前资源时不会卡死，供给器继续尝试后续目标，所有目标均拒收的余量原样保留；
- 达到配置上限后服务端拒绝新增连接并给出明确提示；
- 清空配方类型后连接数归零，原目标不再接收资源；保存并重进世界后未清空的连接及所选面保持不变。

## 12. 订单状态二级步骤

1. 使用包含多个中间产物的配方链下单，例如制作红石火把时让网络先制作木板和木棍。
2. 打开“合成状态”。
3. 在订单尚未推进时检查目标订单下方的二级列表。
4. 左键点击订单标题，再次左键点击同一标题。
5. 等待其中一个步骤完成，并观察状态页自动刷新。
6. 取消另一条进行中的订单，确认其状态变为“已取消”，并继续观察 5 分钟。
7. 使用包含大量步骤的订单保持状态页打开，抓取连续两次无进度变化的状态响应，再让其中一个步骤推进并抓取下一次响应。

预期结果：

- 一级显示最终订单目标和订单总状态；
- 默认只展开列表第一条订单，其余订单保持折叠；展开后的二级只显示全部尚未完成的步骤，格式类似“木板 0/2、木棍 0/1、红石火把 0/1”；
- 同一资源对应的多个未完成步骤合并为一行，数量累计；
- 真实机器当前已返回的产物会更新左侧完成数量，步骤全部完成后从二级列表移除；
- 第一次点击收起详情，第二次点击重新展开；内容超出显示区域时可滚动并显示滚动条；
- 物品、流体和已注册的化学品等 BD 资源使用各自的图标和名称显示。
- 已完成和已取消订单均从各自结束时起保留 5 分钟，随后自动从状态页消失。
- 首次响应包含活跃订单的完整未完成步骤；无变化的后续响应只包含轻量订单索引，不重复携带已完成/已取消订单详情；单个步骤推进时只返回受影响的步骤聚合。

## 13. 同订单并行与机器互斥

1. 准备一张包含两个互不依赖中间产物的订单树，并将两个配方族分别绑定到两台不同机器。
2. 下单后观察两台机器，确认两个中间步骤都能在另一项尚未完成时收到输入并加工。
3. 将两个互不依赖步骤改为使用同一台机器后再次下单。
4. 确认同一时刻只有一个步骤向该机器投料；第一个步骤产物回收后，另一个步骤才获得机器。
5. 在两个中间步骤都未完成时确认父步骤没有提前投料；两者完成后父步骤才变为可执行。
6. 加工期间保存并重启世界，确认多个在途步骤及各自进度能够恢复，且同一机器仍不会收到重复分派。

## 14. 已绑定机器左击配置与防破坏

1. 分别在生存和创造模式中，主手持网络连接器左击已绑定机器。
2. 改为副手持连接器后重复测试。
3. 勾选多个候选配方类型，关闭界面并重新打开。
4. 对含 `activation_item` 与 `offerings` 的仪式配方，将祭坛仅设为 `activation_item`，将多个单槽基座仅设为 `offerings`，以阻挡模式下单。
5. 再取消基座直绑，改用仅接受 `offerings` 的供给器和外部管道给基座投料，以阻挡模式重复下单。
6. 左击未绑定方块、已失效绑定和无管理权限网络中的机器。
7. 在专用服务器上重复创造模式测试，并尝试持续按住攻击键。

预期结果：

- 已绑定机器打开配方类型配置界面，不显示“全部送回网络”按钮；
- 配置由服务端自动保存，重新打开后保持一致；
- 直接绑定方案按材料组将起手物送入祭坛，并把供品分布到多台单槽基座；一个阻挡批次只投送一次配方所需材料，仪式产物从任一参与的直接机器回收后完成该批次；
- 混合方案将起手物直接送入祭坛、把供品送入供给器供管道分发，并继续从参与的祭坛回收产物；供给器不会抢占未分配给它的材料组；
- 创造模式下机器不会被破坏，也不会出现客户端闪碎；
- 主手和副手持连接器都不会绕过保护；
- 未绑定、失效、超距或无权限目标不会打开界面；
- 不持连接器时仍保持原版方块破坏行为。

## 15. 端点优先级

1. 准备两个接受同一配方类型、同一材料组的供给器或已绑定机器。
2. 分别打开两种配置 GUI，确认倒数第二行显示 `-10`、`-1`、当前值、`+1`、`+10`。
3. 把一个端点设为 `10`、另一个保持 `0`，关闭并重新打开界面核对持久化。
4. 下单并确认数值 `10` 的端点先被选择；交换优先级后再次验证。
5. 将高数值端点改为通配材料组、低数值端点显式选择目标材料组，确认显式组仍优先。
6. 连续点击优先级按钮，确认不会触发配方类型的全量重扫或明显卡顿。

## 16. 跨订单配方类型并发

1. 在同一 BD 网络提交两个仅使用不同非普通合成配方类型的订单，例如一个只含 `smelting`、另一个只含 `create:mixing`。
2. 保持前一个订单加工中，确认后一个订单也能开始执行。
3. 再提交两个都包含 `smelting` 的订单，确认后一订单显示“正在等待更早的网络订单”，直到前一订单结束。
4. 提交两个都包含普通 `crafting`、但其他配方类型互不相同的订单，确认 `crafting` 重合不阻止并发。
5. 将 `crafting.maxConcurrentOrdersPerNetwork` 设为 `2`，提交三个配方类型互不相交的订单，确认同一时刻最多执行两个；设为 `1` 后确认恢复严格 FIFO 串行。
6. 在两个不同 BD 网络各提交一个使用相同配方类型的订单，确认两个网络互不阻塞。

## 17. 验收结论

以下条件全部满足时，本功能通过验收：

- 供给器 GUI 无需预先扫描即可打开；
- 未扫描且未配置时提供可搜索、可滚动的 JEI 配方类型单选下拉；
- Create 工作盆扫描后能展示 JEI 返回的多种配方类型；
- 扫描不会自动启用类型，必须由玩家勾选并保存；
- 可以独立启用、取消或同时启用“搅拌”和“压块”；
- 手动下拉只能选一个父类型，服务端验证后重开界面并提供该父类型的子标签；
- 已有扫描候选或现有父类型时不开放候选集外提交；
- 权限、持久化、Jade 展示和库存提取行为符合上述预期。
- 订单状态页默认只展开第一条、能展开全部未完成步骤、正确合并同类资源，并可用左键折叠；已完成和已取消订单均在 5 分钟后消失。
- 同订单内无依赖且使用不同机器的步骤可以并行，同一机器仍严格互斥，父步骤不会越过未完成依赖。
- 同网络订单仅在非普通合成配方类型无交集且未达到配置上限时并行；`crafting` 不参与冲突，不同网络互不阻塞。
- 手持连接器左击已绑定机器可以配置候选配方类型，机器模式没有回库按钮，创造模式不会破坏机器。
- 两种配置 GUI 都能持久化优先级；同组匹配等级内数值更高者优先，显式材料组仍先于通配组。
