# Beyond: Craftlines 0.7.2

支持仪表盘无配方补充容器库存，修复不同 NBT/组件的配方固定与偏好串用，并改进近似候选筛选和排查入口。

本次以上一份正式发布 `0.7.0`（提交 `0bc5381`）为基线，合并尚未发布的 0.7.1 更新。覆盖 Minecraft 1.20.1 Forge、1.21.1 NeoForge、26.1.2、26.2、26.3 NeoForge，以及 1.20.1、1.21.1 的 BD 0.8 专用构建。

### 主要更新

- **无需配方的容器补货**：容器模式的仪表盘只需标记目标资源并设置维持数量，即可从 BD 网络搬运现货，无需配置配方树。缺货时等待网络来货后继续补充；设置的数量是容器内目标总量，而非每次搬运量。
- **先搬运，再按需合成**：配置了配方树时，继续先搬运网络库存，仅为剩余缺口自动合成。自动订单上限只限制创建合成订单，不再阻挡直接搬运。网络库存模式仍需配方。
- **补货状态与订单交付**：无配方的容器仪表盘纳入网络仪表盘状态列表，配置页的配方按钮标为可选，不再提示配方未配置错误。搬运后因订单上限而等待时清除过期错误；旧合成订单的交付保留已配置配方的要求，避免更换无配方目标后按新资源结算旧订单。已有非终态订单继续按原流程执行，避免重复补货。
- **按完整资源身份固定配方**（包含未发布的 0.7.1 更新）：入口配方、手动固定、保存/加载偏好、自动方案及服务端固定链均按完整资源键区分 NBT/组件，不再回退到物品 ID 级记录。抗火药水的固定配方不会接管粗制药水、水瓶等前置节点；显式固定和“仅使用库存”仅对各自精确目标生效。偏好路线不可行时，仍可搜索同一精确目标的其他配方。
- **可逆的近似候选筛选**（包含未发布的 0.7.1 更新）：候选含近似条目时显示“隐藏近似／显示近似”切换，不改变实际选择、偏好或库存身份；无法确认产物身份的条目不会被当成近似项隐藏。显示选择与“存入物品栏／网络”一起保存到客户端偏好文件，后续打开沿用；旧配置默认显示全部。候选标题与按钮分行，切换筛选后返回第一页。
- **更明确的排查入口**（包含未发布的 0.7.1 更新）：合成状态页的智能排查入口移至标题行最右侧的 `!`。“无法下单”仅分析当前规划和缺料；“查看订单排查”跳转只用于“制作卡住”。

### 使用与升级说明

- **无配方补货配置**：将仪表盘贴在目标容器上，标记资源，选择“容器库存”，在样本槽右侧输入维持数量。配方树可以留空；点击数量框外部或关闭界面保存。纯搬运不创建合成订单，仍遵守红石条件、容器可插入空间和精确资源匹配。
- 模组版本统一为 **0.7.2**。从 0.7.0 升级时，网络协议由 34 升至 **35**；客户端和服务端必须配套更新。0.7.2 沿用 0.7.1 开发构建的协议 35。
- 忽略旧的纯物品 ID／粗键偏好，但保留文件中的记录；请按具体物品样本重新选择。已有精确键偏好继续可用。保存了旧粗键固定链的仪表盘需要按精确目标重新配置。
- 组件近似仍仅用于候选排序与显式选择，不改变全局库存相等判断。未插入容器的资源沿原流程退回网络。
- 五个常规构建要求 BD `<0.8`：1.20.1、1.21.1、26.1.2 至少 0.7.30，26.2、26.3 至少 0.7.31。1.20.1、1.21.1 的 BD 0.8 专用构建要求 BD `[0.8.8,0.9)`、CompixelUI 和 Kotlin；1.20.1 / BD 0.8 至少使用 Forge 47.2.18。同一实例只安装一个对应构建。
- 七个构建覆盖自动回归与 JAR 核验。游戏内药水链、容器补货、窗口布局和真实第三方设备流程尚未实机验收；26.3 对应 NeoForge 仍为 beta。

| Minecraft / Loader | JDK | BD 0.7 常规包 | BD 0.8 专用包 |
| --- | --- | --- | --- |
| 1.20.1 / Forge 47 | 17 | 支持 | 支持，Forge 至少 47.2.18 |
| 1.21.1 / NeoForge 21.1 | 21 | 支持 | 支持 |
| 26.1.2 / NeoForge 26.1.2 | 25 | 支持 | 暂无 |
| 26.2 / NeoForge 26.2 | 25 | 支持 | 暂无 |

两个 BD 0.8 专用构建位于 `versions/1.20.1-bd0.8/build/libs` 和 `versions/1.21.1-bd0.8/build/libs`，文件名以 `-for-bd0.8.jar` 结尾。
