# Beyond: Craftlines 0.7.4

在 0.7.3 基础上加入按槽位接受性投料，解决单份有序配方中的重复物品交错排列被打乱的问题。适用于 Minecraft 1.20.1 Forge、1.21.1 NeoForge、26.1.2、26.2、26.3 NeoForge 的 BD 0.7 构建，以及 1.20.1、1.21.1 的 BD 0.8 构建。

## 更新内容

- 物品投料使用槽位级容量预留，允许多槽机器在同一轮接收不同物品；单槽防冲突继续有效。
- 按槽位是否接受材料进行分配，不把配方格号硬编码成机器槽号。某槽被 A 跳过后，后续 B 仍可使用该槽。
- JEI 可识别的有序配方保留原网格位置，空格不压缩为相邻输入；选择索引与网格位置分别保存。
- 同一订单复用物品/槽位兼容性结果，下一轮刷新库存数量与容量；新订单重新检测。
- 网格输入每轮投送一份；供给器独立保存槽位任务，并把一份网格配方保留在同一个供料目标，均分策略不拆散该份配方。
- 真实插入受阻时停止后续投料，保留未完成需求及未插入资源；取消或失效订单的未发送缓存料尝试退回网络。
- 七套产物统一为 `0.7.4`。BD 0.7 保持 `<0.8` 上限，BD 0.8 保持 `[0.8.8,0.9)` 范围。

## 升级与验证

网络协议升级为 **36**，客户端与服务端须同时更新。JEI 磁盘描述缓存升级为 **3**，旧目录将重新采集，以恢复旧缓存缺失的空格信息。

新增 11 项 UT，覆盖动力合成器单容量库存模型、空格、按接受性分配、订单内缓存、单槽防冲突及网格元数据。它们不启动真实 Create 合成器；游戏内验证状态和相关回归场景见 [槽位投料测试文档](SLOT_DELIVERY_TEST_PLAN.md)。本次为打包更新，未创建 tag 或 GitHub Release。

打包验证：七套完整 `build` 通过，共 2722 次测试执行，失败、错误、跳过均为 0。JAR 已核验 ZIP、版本、依赖范围和 Java 字节码。
