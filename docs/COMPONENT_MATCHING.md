# 通用组件候选与实际产物

适用于 Minecraft 1.20.1 Forge、1.21.1 NeoForge、26.1.2、26.2、26.3 NeoForge，以及前两个版本的 BD 0.8 构建。网络协议为 32，客户端和服务端须配套更新。

## 查询和选择

普通配方的来源、预热和精确索引维持原路径。精确匹配失败时，玩家右击资源节点，从原有配方候选列表选择近似候选；界面用 `~` 和提示说明组件存在差异。没有显式选择时，近似候选不能使计划变成 READY。直接点击具体 JEI 配方或此前保存的完整资源选择，也属于指定配方。

查询复用现有按物品 ID/资源粗键分组的目录。索引仅保留对已物化 Catalog 的引用，不为普通条目新增组件解析或完整投影。组件比较只读取该资源桶中的不可变资源键，不枚举 RecipeManager，不调用配方 matches/assemble/getRemainingItems。按共同字段、一致字段及缺失/不同字段的数量确定排序；不把数字接近解释为语义等价。字段快照限制为 128 个叶子、32 层深度、每值 256 字符、每份投影总计 8192 字符，并最多缓存 256 个资源键。无法编码时仍提供稳定候选，不能据此放宽库存身份。

一个候选对应一个配方及其唯一的同资源产物。精确匹配优先；若同一来源配方声明多个同资源组件产物而目标均不精确匹配，则拒绝猜选，需要 JEI 提供独立的变体描述 ID。多个不同配方/JEI 变体始终可以在候选列表中选择。

## 服务端边界

服务端保留现有权限、网络、库存和固定选择检查，只按已选配方 ID 建立请求内的小型索引，复用已读取的产物列表。没有增加全量服务端索引、备选分支搜索或规划期 assemble 试算。不能用客户端上传的组件生成物品。

Step 分别保留逻辑目标 outputKey 和服务端确定的 executionOutputKey：前者用于依赖和玩家选择，后者用于机器输出检测。旧存档缺失 executionOutputKey 时回退为原 outputKey。非精确选择仍必须是同资源类型和同资源来源，不能把廉价配方绑定到另一种物品。

## 执行与记账

原生工作台/锻造/切石继续调用真实配方执行。返回产物包含完整资源键，写入当前步骤的 produced 记录。实际组件不同于预览时，工作台步骤按一次合成执行，不把一次动态结果复制到整批；这类产物的数量若与声明不一致，则在扣料前拒绝。普通固定产物保留原有批处理。

后续工作台原料可使用本订单实际预留、并有对应生产记录的组件键，仍经过真实 Ingredient/matches 校验。其他网络物品不会仅因 ID 相同就获得替代资格。物理机器按 executionOutputKey 精确检测与收取，不猜测任意新出现的同 ID 产物属于订单。

当最终组件发生变化时，背包交付只接受本订单记录过的实际组件键；先对真实栈做容量模拟，避免不同 NBT 需要不同格子时按模板误算。生产记录与订单一起保存，部分完成、重启和后续执行均保留它们。自动补货是精确状态目标，遇到实际组件不同会暂停并提示检查，避免不断生产无法计入目标库存的变体。

## 默认 profile

默认发行包不再携带 slashblade.json。白鞘式动态产物由通用候选选择及实际产物记录处理，生产代码不检查 slashblade、IronJetpacks 或 ModernChickens 名称。已有用户自定义的显式 profile 仍能读取，作为高级兼容覆盖。规划缓存格式升至 6，使旧缓存内的默认 SAME_RESOURCE 策略失效。

## 回归验证

- ComponentRecipeCandidatesTest：无选择不能自动近似；多个配方可指定；精确计划和材料量不变；不同资源禁止关联；歧义输出不猜选。
- ComponentLookupFastPathTest：1000 条目录下反复精确查询不重新序列化组件。
- WhiteSheathOutputPolicyTest：无 profile 的实际状态绑定，未记录的其他武器拒绝。
- ProducedReceiptPersistenceTest：所选产物、实际记录和部分执行状态往返保存。
- ActualOutputCapacityTest：不同组件占不同背包格，模拟不改变真实栈。
- 原有炼药、火箭、普通规划与 BD 分包用例继续执行。

这些是程序级回归测试，不代表已加载真实拔刀剑和所有第三方机器完成游戏内验收。
