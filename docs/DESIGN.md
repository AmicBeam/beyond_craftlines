# Beyond: Craftlines 统一设计文档

本文档描述当前 `beyond_craftlines` 源码已经实现的功能和约束。它是本项目唯一的设计文档；若文档与代码不一致，以当前源码、注册表和模组元数据为准。

## 1. 项目定位

Beyond: Craftlines 是同时面向 Minecraft 1.20.1 Forge、1.21.1 NeoForge 和 26.1.2 NeoForge 的 Beyond Dimensions（下称 BD）下单附属模组。除非明确标记为版本专用，本文所有功能与约束均适用于三个版本。

它负责把服务端已加载的配方组织成可执行订单，并使用 BD 网络库存完成递归备料、普通合成、原生网络炉加工或第三方机器加工。

项目基础信息：

| 项目 | 当前值 |
| --- | --- |
| 模组 ID | `beyond_craftlines` |
| 支持矩阵 | `1.20.1` / Forge 47 / Java 17；`1.21.1` / NeoForge 21.1 / Java 21；`26.1.2` / NeoForge 26.1.2 / Java 25 |
| 必需依赖 | 各版本对应的 Beyond Dimensions 与 JEI 构建，具体版本见各自 `gradle.properties` |
| 可选显示联动 | Jade |
| 当前版本 | `0.1.0` |

本模组不再包含构象捕获、测试维、沙盒试产、试产报告、稳态产线、图纸复制或相关命令。这些内容不属于当前 JAR。

## 2. 玩家可见内容

当前只注册以下内容：

| 类型 | 注册名 | 作用 |
| --- | --- | --- |
| 物品 | `beyond_craftlines:network_linker` | 将原版或第三方机器及配方类型关联到当前 BD 网络；潜行使用可解绑 |
| 方块/方块物品 | `beyond_craftlines:craftline_provisioner` | BD 联网的订单输入交付端点，只接受订单内部写入 |
| 菜单 | `beyond_craftlines:craftline_order` | 查看 JEI 指定产物的递归树、设置数量和阻挡模式、下单及取消订单 |
| 创造模式页 | `beyond_craftlines:main` | 收纳网络联结器和合成链供给器 |

网络联结器不可堆叠。供给器继承 BD 的联网方块语义，并持久化自己的动态资源库存。

## 3. 总体数据流

```text
任意界面中的 JEI 配方（玩家须有有效 BD 网络）
        │ Craftlines 按钮
        ▼
服务端打开订单菜单并固定 networkId
        │
        ├─ 服务端：签发库存 revision + 配方 epoch 的分页快照
        ├─ 客户端后台：候选搜索、配方/原料 resolution、配方树
        ├─ 客户端：分页上传完整建议
        ▼
服务端校验权限、版本与完整 resolution，并线性复算
        ▼
短期缓存已验证 RecipePlan；下单时再次校验 revision/epoch
        ▼
持久化 RecipeOrderJob
        ▼
每 tick 按网络 FIFO 串行推进
        ├─ crafting ───────► 服务端模拟原配方
        ├─ smelting 系列 ──► BD 网络熔炉/高炉/烟熏炉
        ├─ 第三方配方族 ───► 直接绑定机器的物品能力
        └─ 供给器配方族 ───► 交付订单输入后推进步骤
```

服务端是库存变化、计划有效性、订单状态和绑定权限的唯一权威。客户端可以基于服务端签发的只读库存快照搜索建议配方树，但建议必须由服务端按当前配方注册表和相同快照版本完整复算后才能下单。

第三方机器配方可能把原版 `Recipe#getIngredients()` 保持为空。此时规划器从配方公开 input 对象的 `getRepresentations()` 读取候选，并通过 BD `IStackKey` 注册表转换为统一资源。物品、流体以及已加载 Mekanism 联动所注册的化学品等资源共同参与客户端树、库存抵扣、缺料与网络提取汇总、计划签名、服务端校验、订单预留和机器投送。

## 4. JEI 入口与订单界面

### 4.1 JEI 入口

JEI 插件为存在物品产出且具有注册 ID 的配方增加网络联结器图标按钮。拥有有效 BD 主网络的玩家默认在任意界面打开 JEI 时均可看到并使用；没有网络时不显示。客户端配置可将其进一步限制为仅在 BD 网络菜单中可用。点击后会同时传递产物 ID 和当前 JEI 配方 ID；订单树根节点固定使用该配方，自动规划和玩家 resolution 只作用于后续层级。

点击后客户端发送目标物品 ID 和当前 JEI 配方 ID。服务端优先从仍打开的 BD 网络菜单取得网络；来自其他界面时使用玩家当前的 BD 主网络。服务端校验成员关系、具体配方、产物和网络可用配方族后打开 Craftlines 订单菜单，客户端不能自行指定任意网络。玩家未设置有效主网络时会收到需要连接网络的提示。

### 4.2 订单界面

界面当前提供：

- 产物搜索与分页列表；
- 以入口所在的具体 JEI 配方作为不可自动替换的根配方；
- 可平移、缩放的 EMI 风格递归配方树：目标在上、原料按层向下展开，同一配方层内的相同物品合并并累计数量；
- EMI 风格原料图标网格：成功计划显示本单实际从网络取用的物料，失败计划显示缺料；图标按多行排列、数量叠加显示，悬浮展示精确数量与库存，超出区域时提供滚轮和可见滚动条；
- 悬浮有生产配方的节点时，在物品提示中嵌入所选直接原料 → 单批产物的图形预览，并显示配方族和配方 ID；
- 当前网络中目标物品数量；
- `long` 制作数量输入；
- AE2 风格阻挡模式开关；
- 最近 20 条本人订单的状态、步骤进度和错误信息；默认只展开第一条订单的尚未完成二级步骤，其余订单保持折叠，二级步骤按产物合并并显示“本步已回收/仍需产出”，左键订单标题可折叠或展开；
- 取消本人非终态订单。

已完成和已取消订单均在状态页保留 5 分钟后自动移除；失败订单仍按服务端终态历史条数上限保留。
订单状态详情以稳定消息代码和参数持久化，客户端按当前语言渲染；旧存档中的已知英文状态会在读取显示时兼容转换，未知异常只显示本地化通用错误，不向玩家暴露原始异常文本。

菜单创建时缓存客户端可见配方及“产物到候选配方列表”的索引。目标、数量或覆盖项变化后，客户端经过短暂防抖请求只读库存快照；快照带库存 revision、完整配方 epoch、服务端深度/节点预算并按 256 项分页。客户端先在渲染线程复制不可变配方目录，再在后台线程搜索建议 resolution，搜索结果按每页最多 256 个配方选择和 256 个 ingredient 选择上传。服务端重新验证菜单权限、快照版本及每个实际使用的配方/ingredient，使用固定 resolution 线性复算计划；固定复算只核对数量、库存、配方可用性和设备族，不消耗候选分支节点或时间预算。客户端漏传任一实际选择都会被拒绝，不会回退成服务端分支搜索。验证成功的计划只缓存 30 秒，下单时库存 revision 或配方 epoch 已变化则拒绝并要求刷新。

客户端配方目录捕获采用每 client tick 至少 16 条、默认最多 256 条且约 2ms 的自适应预算；条目上限可由客户端配置调整，该阶段不占用服务端 CPU。捕获完成后的分支搜索在客户端后台线程执行，目录按配方管理器及配方 ID 集合缓存，只有配方重载后才重新建立。优化节点预算按唯一物品 ID 计数，同一 ID 即使在多条分支或以不同组件出现也只计一次；非物品资源按完整资源键计数。节点或时间预算耗尽后只停止继续比较候选，当前确定分支仍会完成，已经得到的完整可制造建议仍会上传并接受服务端复算。

服务端复算结果仍按 nonce 和连续页码回传，客户端收齐全部页面后才原子重建树并启用下单按钮；页码不连续、过期后台任务或旧 nonce 的结果会被丢弃。同一界面在 1 秒内调整数量或 resolution 会复用客户端只读快照，只重跑后台搜索；从节点进入 JEI 配方查看页再返回同一个订单界面实例时，保留数量、树、已验证建议和下单按钮状态，不重新索引或规划。服务端返回结构化 `stale` 时立即废弃缓存并自动刷新。库存快照和建议上传均最多 64 页，未完成上传 10 秒后失效。

订单数量表示必须新制造的数量，而不是目标库存水位。网络中已有的最终产物只用于右侧“网络已有”显示，服务端规划、材料预留、实际提取和“本单将从网络取用”汇总均明确排除与最终产物等价的资源。

同一产物在一份计划中共享一个配方选择。树中每级输入先按“当前节点尚缺数量 ÷ 单次配方产量”向上取整得到加工次数，再将非复用槽位的单次用量乘以加工次数；容器或稳定工具等复用槽位仍只计一份。树构建期间使用组件感知的库存账本累计扣减，同一批库存不会被多个节点重复判定为可用；库存完全满足的节点为绿色叶节点，部分满足的节点为橙色并显示本单总需求，随后只按剩余缺口继续展开下级原料。同一父配方层内解析成相同物品的重复 ingredient 槽位按完整组件键聚合数量，再创建子节点，因此倍率会逐级向下传播。合并节点保留全部来源槽位，玩家选择候选时会原子应用到整组槽位。启用默认显示折叠时，同一完整资源键（含物品组件）只保留最靠近树根的一次完整节点，后续更深层的重复位置显示紫色跳转引用；没有服务端汇总指标的本地预览会把各重复位置的需求量、取用量和制造量累计到该完整节点。左键引用会将视图定位到浅层完整节点。引用只改变显示，不合并服务端规划步骤或预留。点击包含多个候选的 ingredient/tag 节点会打开 EMI 风格物品网格，网格支持分页和滚轮，当前项高亮；右击产物节点仍可轮换统一使用的配方，按住 Ctrl 右击会清除相应覆盖并恢复自动选择。玩家选择随预览和下单请求发送，服务端按当前配方注册表重新验证，客户端不能提交不产出目标物的配方或不匹配原始 ingredient 的物品。当前展开链路发生循环时仅以红色警告节点截断，不创建跳转引用。

玩家在候选网格中普通点击配方或 Tag/ingredient 物品后，该选择会立即成为默认偏好，不需要额外按键。配方候选格使用该配方的首个直接材料作为辨识图标，无可解析材料时才回退到产物图标；悬浮展示产物、完整直接原料预览和唯一一行配方类型，格式与机器“已并入网络”提示一致，为“注册表类型 ID（JEI 本地化分类标题）”，无法取得本地化标题时只显示类型 ID。树节点的配方图使用服务端聚合后的实际输入和计划产出数量，候选选择弹窗才显示单次配方原子数量。偏好写入客户端全局文件 `config/beyond_craftlines-planner-preferences.json`，跨单机存档和多人服务器共用；当前实例不存在或不再匹配的配方、槽位和物品会在加载时忽略，服务端仍会在每次预览和下单时重新校验实际选择。

树布局参考 EMI：根节点在画布上方居中，兄弟原料横向排列，深度沿纵向增长。布局只在树内容或 resolution 变化时重建；缩放、平移和悬停期间仍按 Minecraft GUI 的逐帧模型绘制，但会先裁剪视口外的节点和连线，视口外节点不会调用物品栈渲染。

循环警告节点只用于标出再次遇到的祖先资源，不消耗库存，也不继承该资源的全局累计指标。服务端会回滚造成回环的配方分支，把直接发起回环的上级资源按其累计需求记为缺料；该上级节点显示红边，并与右侧缺料汇总保持一致。

固定客户端方案的服务端复算不调用候选分支数或搜索耗时预算，包括原料候选枚举与变体校验；这些预算只约束自动搜索。固定链路仍执行递归深度、循环、配方合法性和库存充足性校验，循环或缺料返回正常缺料结果，不转换成服务端规划上限错误。

客户端方案上传完成后，服务端短期缓存完整的已验证计划。点击下单时只校验配方纪元并原子预留计划中的网络原料，不再重复规划整棵配方树；订单菜单的打开数据同时携带新订单摘要，因此页面先显示订单，再由状态同步补齐步骤明细。

### 4.3 阻挡模式

阻挡模式只影响真实机器步骤，不改变工作台模拟合成：

- 开启：每次只发送一次配方所需输入，上一批产物回收完成后才发送下一批；目标机器中仍存在该配方任一输入时暂停发送。
- 关闭：本步骤的剩余批量按机器可接收容量持续投料，不因已有同配方输入而阻挡。

每台真实机器同一时间只会被一个活动订单占用。每个 BD 网络同一 tick 只推进最早创建的一个活动订单，其余订单保持等待，从而避免同网络库存事务互相穿插。运行时每 tick 先用一次线性扫描建立“已认领网络”和“已占用机器”索引，机器预订不再为每个候选订单重复扫描全部活动订单。

## 5. 配方发现与递归规划

### 5.1 可见配方

规划器读取服务端 `RecipeManager`，只保留：

- 非 incomplete；
- 至少有一个 ingredient；
- 存在非空物品产出；
- `crafting` 配方，或其配方族在当前网络具有可用执行端点。

可见配方按配方 ID 排序并按 `RecipeManager` 弱引用缓存；数据包同步和客户端配方更新时清空缓存。

### 5.2 配方族

原版类型映射为短族名：`crafting`、`smelting`、`blasting`、`smoking`、`campfire_cooking`、`stonecutting`。其他配方类型使用服务端注册的完整 namespaced ID。

第三方机器关系来自 JEI 正式 recipe catalyst：

1. 客户端从 JEI runtime 建立“催化剂物品 → category UID”索引；
2. 绑定时最多发送 32 个 category UID；
3. 服务端只接受当前已加载配方族中同名的类型；
4. `minecraft:*` UID 去掉命名空间后匹配原版短族名，第三方 UID 必须与服务端 `RecipeType` ID 一致。

实现不包含 Mekanism、Goety、群峦传说或其他具体模组的硬编码分支。

### 5.3 确定性规划

规划从 BD 网络统一资源库存快照开始。请求数量表示“本次需要制造的数量”，已有目标产物不会抵扣请求。

当一个产物有多个配方时，玩家已保存的配方和 ingredient 偏好优先于自动建议。未固定部分由客户端建议规划器在同一预算内试规划候选分支，依次按缺失材料总量、步骤数和配方 ID 选择当前最佳分支；找到完整可制造分支或优化预算耗尽后即可停止继续比较。配方 ID 只用于同分稳定排序，不再决定主要选择结果。建议上传后，服务端要求每个实际产物都已经固定配方，因此权威复算不再遍历候选分支；若配方已经卸载或不再产出目标物，服务端拒绝建议。

Ingredient 有多个候选时按以下顺序选择默认值：

1. 网络现有库存数量更多；
2. 可由当前配方图继续制造；
3. 物品 ID 字典序。

自动选择会先试上述基准组合，再逐槽尝试一个备选成员并比较完整子树结果。候选规模是 `1 + 各槽备选数之和`，不会对多个 tag 槽做笛卡尔积；如果最优方案必须同时替换多个槽，玩家仍可在树中手动固定这些 ingredient。

同一配方中最终选择为相同物品的 ingredient 会先合并，再向下递归。环路、达到深度上限或找不到配方时，相应需求进入缺失材料；存在任何缺失材料时拒绝创建订单。

玩家可按“配方 ID + ingredient 槽位”固定 tag/OR ingredient 的具体物品。服务端要求该物品仍存在于 ingredient 候选集合中。最终选择既写入聚合材料需求，也逐槽写入订单步骤；普通合成执行时只从 BD 网络选择对应物品 ID 且通过原始 `Ingredient.test` 的真实 `ItemStackKey`，避免执行阶段换成另一个 tag 成员。

### 5.4 数量安全

订单数量、计划步骤、BD 存储转移和产量均使用非负 `long`。加法、乘法和向上取整使用饱和运算，超过范围时封顶到 `Long.MAX_VALUE`，不会发生有符号溢出或回绕。

客户端搜索受服务端下发的递归深度、优化节点数和时间预算约束；优化预算耗尽只会收敛到当前最佳候选，不会单独拒绝建议。服务端对客户端固定选择只沿已选链路线性复算，不消耗候选节点或自动搜索时间预算；仍保留递归深度、协议分页/选择数、循环检测以及配方和库存权威校验。最终缺料、选择无效、提案不完整或超过递归深度时才会拒绝下单。

## 6. 工作台模拟合成

`crafting` 步骤不直接把输入替换成静态结果，而是调用服务端原始 `CraftingRecipe`：

1. 按计划固定的 ingredient 物品，从 BD 网络快照为每个槽位选择仍通过 `Ingredient.test` 的真实 `ItemStackKey`；
2. 构造 1×1 至 3×3 的 `CraftingInput`，并调用 `matches`；
3. 调用配方自己的 `assemble` 和 `getRemainingItems`；
4. 校验实际产物仍是计划目标；
5. 模拟检查网络能否容纳产物和返还物；
6. 提取输入并写回动态产物、容器、工具和其他返还物；
7. 任一步骤失败时回滚本次已提取或已插入的内容。

这使定制配方、动态组件、容器返还、耐久工具和不完全消耗物品走同一套原配方语义。

批处理规则：

- 普通可堆叠输入按网络可用量一次结算多次合成，不按每 tick 一个产物执行；
- 输入与返还物的物品和组件完全一致时视为可复用催化剂，整个批次只要求并消耗一份，然后返还一份；
- 返还物是同一物品但组件发生变化时视为有状态工具，本轮只执行一次，让下一轮使用更新后的真实状态；
- 批量返回与消耗都按 `ItemStackKey` 聚合并使用饱和 `long` 运算。

每个成功的模拟合成批次之后，下一普通合成节点至少等待 `virtualCraftingNodeIntervalTicks`。

## 7. 真实机器执行

### 7.1 BD 原生网络炉

仅原生支持：

| 配方族 | BD 机器 |
| --- | --- |
| `smelting` | 网络熔炉 |
| `blasting` | 网络高炉 |
| `smoking` | 网络烟熏炉 |

这三类机器不允许使用网络联结器重复绑定。注册表监听 BD 的绑定/解绑事件以及区块加载、卸载和维度卸载，并按“网络 ID + 配方族”建立索引。

订单从同网络库存提取物品并直接写入炉子的输入存储。产物可能由 BD 自身自动回网，也可能仍在炉子输出存储中，因此订单同时观察网络目标增量和炉子输出；只把本次基线之后出现的产物计入订单，避免误领旧产物。

### 7.2 直接绑定配方机器

网络联结器允许直接绑定原版及第三方模组的方块实体，但拒绝 `beyonddimensions` 和本模组命名空间下本身已属于 BD 网络的组件。绑定要求：

- 玩家管理当前 BD 网络；
- 目标区块已加载且距离玩家不超过 8 格；
- JEI 将目标方块物品登记为至少一个可映射配方类型的催化剂；
- 目标至少公开一个对应加载器的方块物品处理能力（Forge/NeoForge `IItemHandler`）。

直接绑定不需要供给器。订单通过目标方块无侧面及六个侧面的 BD 已注册资源能力：

- 模拟并选择接收能力最大的 handler；
- 从 BD 网络提取机器当前可接受的输入；
- 无法插入的余量立即退回网络；
- 记录下单前目标产物基线，只收取基线之后新增且可提取的产物；
- 对多输出配方持续收取目标以外的实际副产物并写入网络；已有副产物未清空时暂缓派发，避免把旧产物计入本单；
- 网络暂时无空间时保留机器产物并继续等待；
- 机器被拆除、更换、卸载后不可验证或失去物品能力时，订单暂停或进入错误状态。

通用能力无法可靠区分同种物品输入和输出，因此当前拒绝“目标产物同时也是本配方物品输入”的第三方机器步骤。机器配方公开的流体、化学品等输入会通过 BD 已注册的相应方块能力供应；未被配方公开为输入的能量或隐藏工艺条件仍由机器或其他系统自行满足。

### 7.3 合成链供给器

供给器不是直接机器绑定的必需组件，而是独立的订单输入交付模式：

1. 供给器先绑定到 BD 网络；
2. 玩家持网络联结器潜行右击供给器，将其设为临时选择；
3. 再右击 JEI 已登记的第三方机器/催化剂方块，只把识别到的配方类型加入所选供给器的候选集；
4. 普通右击供给器可随时打开 GUI，玩家只能在已扫描候选中勾选，修改后自动保存，不提供手工填写；未扫描时 GUI 不显示类型选项；供给器总共只有一个候选且当前未配置时，绑定流程在服务端自动选中并立即启用；
5. 对应已启用配方族执行时，订单把本步骤输入原子交付到供给器，然后立即推进，不负责外部机器加工和产物回收。

供给器拒绝玩家和管道写入，只有订单事务能短暂打开写入门。外部能力和玩家可以提取；GUI 的“取出一组”按钮每次取出一种资源的一组物品。Jade 只显示供给器已勾选启用的配方类型。

网络联结器在空气中使用会清空当前所选供给器的候选和已启用配方类型。候选、最近一次成功扫描的目标方块 ID 及其“选取方块”物品堆栈保存在供给器方块实体；物品堆栈同步为实例级模型数据，其 GUI 物品模型被压平、缩放为 8×8，并以保留原贴图完整 alpha 的透明渲染层合入供给器四个水平侧面的纯色 8×8 底板，不使用悬浮方块实体贴片。顶部仍保留供给器自身图案。客户端收到目标变化后会刷新模型数据并立即重建对应区块网格，无需等待下一次方块更新。已启用类型保存在绑定 SavedData。服务端保存配置时会再次验证已选类型是候选子集。供给器模式与第三方机器直接并网是两条独立路径。

## 8. 绑定持久化与视觉

绑定记录保存在主世界 SavedData `beyond_craftlines_bindings`，包含所有者、网络 ID、维度、坐标、设备类型、JEI 类型、配方族和绑定时方块 ID。运行时按玩家、网络、位置和供给器端点建立索引。

普通绑定：

- 网络联结器右击第三方机器：绑定；
- 潜行右击已绑定第三方机器：解绑；
- 只有目标网络管理员可以解绑；
- 方块被破坏时移除关联记录；
- 加载后会校验维度、方块 ID、网络和能力，防止坐标处更换方块后沿用旧绑定。

直接绑定的第三方机器会显示 BD 风格的黑蓝青三层线框。实现使用 `RenderType.lines()` 在方块实际碰撞/轮廓包围盒外分层绘制，不替换方块材质，因此不会与原材质争夺同一深度面而产生材质闪烁。

客户端登录、切换维度和绑定变化时接收服务端快照。快照按区块索引，渲染只遍历玩家附近区块，并再次校验距离、区块加载状态和方块 ID。

## 9. 订单状态与持久化

订单状态：`QUEUED`、`RUNNING`、`PAUSED`、`COMPLETE`、`CANCELLED`、`ERROR`。

`RecipeOrderJob` 保存：

- 订单 UUID、所有者和网络 ID；
- 目标、请求数量和阻挡模式；
- 已解析步骤及当前步骤索引；
- 下次普通合成允许时间；
- 外部机器等待上下文，包括机器位置、产物基线、目标数量、已收取数量和剩余输入。

订单保存在主世界 SavedData `beyond_craftlines_recipe_orders`。重启后可继续等待真实机器和推进剩余步骤。没有状态变化时不会重复标脏存档；终态历史按配置只保留最新若干条。

取消只允许订单所有者操作，并且不会撤回已经送入机器、供给器或已经完成的步骤。

## 10. 网络协议与安全边界

当前协议包括：打开菜单、请求分页规划快照、分页上传客户端建议、同步服务端验证后的 resolution、消费已验证计划提交订单、取消订单、请求订单状态、请求网络物品数量、绑定/解绑机器以及同步绑定视觉。

所有改变状态的请求都在服务端重新校验菜单类型、玩家身份、网络上下文、距离、手持物品、目标资源 ID 和权限。客户端提供的 JEI category 只是候选，必须与服务端已加载配方类型再次匹配。

以下协议上限固定，不开放配置：

- 字符串最大 256 UTF-8 字符；
- 单次绑定最多 32 个 JEI 配方类型；
- 绑定目标必须在玩家 8 格内；
- 订单数量必须为正 `long`，非法或非正输入归一为 1。
- 规划库存快照和建议上传每页最多 256 项、最多 64 页；必须按 nonce 和连续页码组装。
- 已验证客户端计划最多缓存 30 秒，未完成的建议上传最多保留 10 秒。

这些上限用于保证解码和权限边界，不属于玩法调节项。

## 12. 性能设计

当前实现采用以下约束避免随配方、订单或绑定数量失控：

- 配方规划具有深度、节点和时间三重预算；
- 数量计算使用饱和 `long`，不因复杂树溢出；
- 同配方重复 ingredient 在递归前聚合；
- 可见配方和产物索引缓存，并在配方重载时失效；
- 普通稳定合成按长整型批次执行，不按十亿次循环；
- 只有有状态返还工具逐次模拟；
- 订单调度只扫描受配置限制的活动订单，终态历史有界；
- BD 原生网络炉按网络与配方族索引；
- 绑定与供给器记录按常用查询维度索引；
- 客户端绑定边框按区块索引并受距离限制；
- 无状态变化的等待 tick 不重复写脏 SavedData。

## 13. 当前兼容边界

本模组承诺的是基于 BD `IStackKey` 与已注册能力的通用配方和机器编排，不承诺理解每个模组的内部工艺状态。

- 工作台类定制配方：由原配方 `matches/assemble/getRemainingItems` 决定，支持动态结果和返还物。
- 第三方机器：要求 JEI catalyst、同 ID 服务端 RecipeType、已加载配方和可用 `IItemHandler` 同时成立。
- 配方中的 `energy`、`power`、`FE` 等数值元数据不视为 ingredient，也不推断单位或换算关系；机器能量与其他专用工艺条件由真实机器自行处理。公开为 ingredient representations 且能转换为 BD 已注册资源键的物品、流体、化学品等真实输入会正常规划与供应。
- 配方和 ingredient 选择当前按输出物品、配方槽位作用于整棵订单树；相同输出或相同配方槽位的重复节点共享选择。
- Ingredient 规划按玩家固定或默认选择的物品 ID 统计；真正合成时按该物品 ID、BD `ItemStackKey` 和原配方匹配共同选择具体组件。
- 真实机器无法证明某个新产物一定由本订单产生，只能通过下单前基线与数量增量隔离；机器应避免被其他自动化同时操作。
- 机器或相关区块必须已加载，模组不会主动加载区块。
- 供给器交付后步骤即视为完成，它不等待或回收外部加工结果。
