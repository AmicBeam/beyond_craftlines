# 0.7.4 槽位投料测试与回归

本次更新以 `d690e3b` 的 0.7.3 为代码基线，包含槽位投料提交 `1b4c9f9`，并将七套产物统一打包为 0.7.4。本文供功能验收与后续回归使用。

自动化测试验证分配算法、配方元数据及批次推进；真实 Create 合成器、无线转发、联机和存档恢复另列为游戏内验收。未执行的实机案例均为“待执行”，不能用构建通过代替。

## 1. 本次更新内容

| 更新 | 行为与验收重点 |
| --- | --- |
| 槽位级容量预留 | 按材料顺序在本轮库存快照中预留可接收槽位，允许同一多槽机器接收 A、B 等不同物品，避免先把所有 A 集中发送；单槽仍不能被不同材料重复预占。 |
| 按接受性分配 | 配方格号不是固定机器槽号。A 被槽 0 拒绝后可进入槽 1；槽 0 仍可接收后续的 B。 |
| 保留原配方空格 | JEI 采集、上传、配方身份、规划材料及订单存档保留网格位置。分配时空格占用下一个未分配位置，不发送占位物品；JEI 隐藏的空格也不应压缩掉。 |
| 订单内兼容性缓存 | 同一能力对象、同一物品键与槽位的接受性结果在订单内复用，包括下一轮及同订单的后续配方步骤；新订单重新检测。每轮仍刷新真实库存数量与容量。 |
| 逐份投送网格配方 | 具有网格位置的输入每轮只投一份；上一份完成后推进下一份，即使用户未手动开启阻挡模式。 |
| 供给器定位转发 | 独立保存待转发的槽位任务，不依赖内部合并库存的遍历顺序。一份网格配方保留在同一个供料连接目标，均分策略也不拆散这一份。 |
| 插入失败与返还 | 真实插入不足时停止后续投料，保留未完成需求；未插入的网络提取资源返还，供给器保留被拒绝的缓存料。取消或失效订单的未发送缓存料尝试退回网络。 |
| 升级兼容 | 网络协议由 35 升至 36；JEI 磁盘描述缓存由 2 升至 3，旧目录重新采集以恢复空格信息。客户端与服务端须同时更新。 |

识别范围：原网格采集入口识别 `ShapedRecipe` 及其子类，且要求 JEI 输入视图能对应完整网格或非空格列表；不能对应的布局不会被猜测为固定网格。兼容性缓存不等于全局库存相等规则，也不替代真实 `insert` 的拒绝/容量处理。

## 3. 测试准备

1. 使用独立测试世界或生产存档副本，记录 MC、加载器、BD、JEI、Create、Craftlines 版本及 JAR SHA-256。
2. 建立一个有管理权限的 BD 网络，准备网络连接器、合成链供给器、可观察的产物输出和回收线路，保持相关区块加载。
3. 放置一组 3×3 动力合成器，面向一致，设置合法的合成箭头、动力和产物出口。用扳手将**输入库存**连成一组；仅摆在一起或连接合成箭头不等于共享输入库存。
4. 首轮只绑定组内一个成员，排除同组多个入口与其他自动化设备并发写入的干扰。组的网格宽度与测试配方一致。
5. 准备下列测试专用有序配方：A 为铁锭，B 为金锭，每格一个，单次产出一个独立测试产物。按所装 Create/MC 的实际配方格式在测试数据包注册，并记录注册 ID；不要将测试配方装入生产包。
6. JEI 显示必须与下图一致。空格使用合成器槽位盖板，必要时用该版本支持的触发方式完成含空格配方。先确认手工按图填料能合成，之后清空网络外的输入与残留产物。
7. 分别准备直连方案和供给器方案，测试时只启用一种；记录材料组、过滤、优先级、阻挡模式及供料策略。

### 测试图案

`.` 表示空格，不是可投送物品。位置从面向配方的一侧观察，按从上到下、每行从左到右记录。

```text
G1：交错九格，5A + 4B    G2：前置空格及整行空格，2A + 1B
A B A                    . A .
B A B                    . . .
A B A                    B . A

G3：含中间及末尾空格，3A + 2B
A B .
B . A
. A .
```

G2 对应非空格索引 `[1, 6, 8]`，G3 对应 `[0, 1, 3, 5, 7]`。暂停动力或使用录像，在合成器搬运材料之前保存一次完整输入图案；不能只看“最终有产物”来判定槽位正确。

每例记录下单前后网络、机器、供给器的 A/B 数量与产物数量。对于无返还物的这些测试配方，初始总量与结束总量的差必须等于实际成功次数的配方消耗；失败、取消和重试不得额外吞料或复制资源。

## 5. 游戏内功能验收

以下均为**待执行**。P0 为核心验收，P1 为异常与恢复验收。每个案例都应记录实际结果、截图/录像和日志，而不是提前填写“通过”。

### F-01 P0 单份交错九格直连

- 步骤：使用 G1；网络准备 5A、4B；清空合成器；直接绑定并下单一份，先暂停动力观察填料，再恢复动力回收产物。
- 预期：输入严格为 G1，不能变成前五格 A、后四格 B；最终恰好产出一份，消耗 5A、4B，无剩余待发送材料。
- 证据：完整九格图、订单完成状态、输入/产出计数。UT-01 仅覆盖其中的分配算法。

### F-02 P0 原配方空格

- 步骤：分别使用 G2、G3，各下一份；配置盖板并先确认手工图案可制作；观察 Craftlines 的实际填料位置。
- 预期：G2 前置空格、整行空格及 G3 中间/末尾空格均保持为空；非空材料不向前压缩，不向盖板槽发送物品；两种配方各完成一次，消耗与图案一致。
- 证据：JEI 原图与输入实际位置对照、消耗计数。G3 的末尾空格还需要实机确认。

### F-03 P0 多份订单及自动逐份投料

- 步骤：G1 下单 10 份，先关闭用户阻挡模式，再开启重做；每轮完成后观察下一轮，最后检查总量。
- 预期：每轮只进入 5A、4B，完整图案未被不同批次混合；共 10 份产物，消耗 50A、40B。前一轮未完成时不能把下一轮 A 填进其他配方格。
- 证据：至少两轮连续录像、总消耗及最终订单状态。

### F-04 P0 供给器的槽位任务

- 步骤：解除直连，改为一个供给器向同一合成器组供料；对 G1、G2 分别下一份。检查供给器内部同种物料合并后的转发结果。
- 预期：仍得到正确网格，发送不依赖缓存库存的物品遍历顺序；G2 空格不丢失，最终供给器无遗留输入。
- 证据：供给器库存、目标输入图案、产物与消耗。

### F-05 P0 多连接与供料策略

- 步骤：同一供给器连接两组独立、空闲、同尺寸的合成器；依次使用轮询、最近、最远、均分策略，分别对 G1 下一份；再下多份验证轮次。
- 预期：一份九格材料完整进入同一组，另一组不能只收到其中几种材料。不同份之间可以按策略选择目标；均分策略也不能把一份网格配方拆开。
- 证据：每组材料/产物计数及供料策略。普通非网格均分行为另见 R-04。

### F-06 P1 新一轮前的残留输入

- 步骤：在目标组预放一个 A，另一次改为放不相关物品，然后下单 G1；记录等待状态，清空库存后继续。
- 预期：新网格轮次等待目标清空，不把残留物按同类总量抵扣，也不在残留物旁拼装这一份；清空后正常完成，不重复扣料。

### F-07 P1 真实插入拒绝与重试

- 步骤：使用可控制拒绝时机的测试库存或调试夹具，在预留后、实际插入前让某个目标槽拒绝；先确认该夹具确实触发真实插入不足。记录已插入和未插入数量，解除拒绝后继续。
- 预期：拒绝点之后的材料不继续发送，不转投其他格；未插入的提取量退回网络/供给器，解除拒绝后只补未完成需求，无复制或吞料。
- 限制：普通 UI 操作不能可靠保证命中预留与插入之间；未能构造这一时序时记为“阻塞：缺少夹具”，不能用静态槽位拒绝代替该案例。

### F-08 P1 存档与重启恢复

- 步骤：分别在供给器已缓存材料但尚未发送、以及已部分插入时保存并停止测试实例；重启后保持相同连接与配方，完成订单。
- 预期：材料需求、网格位置、待转发顺序和已选连接身份恢复；已成功插入的部分不重复发送。新运行会话允许重新建立兼容性缓存，不要求探测计数跨进程保存。
- 证据：重启前后的三处库存、连接、订单进度与最终产物。

### F-09 P1 连接变化及卸载

- 步骤：部分发送时卸载目标区块，恢复后继续；另起一单，在部分发送后更换已选连接的目标/面或移除目标方块。
- 预期：不可用时不把剩余材料转投其他无关网格；相同目标恢复后可继续。连接身份改变时保留材料并等待处理，不声称会自动适配新连接；如需取消重下，按 F-10 核对返还。

### F-10 P1 取消及缓存返还

- 步骤：分别在供给器未发送、部分发送时取消订单；检查网络、机器和供给器。再测试网络暂不可用，恢复网络后观察返还。
- 预期：尚未投往机器的缓存料停止发送并尝试退回网络；网络拒绝时仍保留待返还资源。已进机器的材料单独计量，不能同时返还为一份新原料。取消后新订单不能覆盖尚未处理的槽位队列。

### F-11 P1 缓存的升级与重建

- 步骤：先保留协议 35 构建产生的 JEI 目录缓存；客户端和服务端一起更新 0.7.4，打开 G1、G2；退出重进后再打开。另在测试实例尝试客户端/服务端协议不匹配。
- 预期：旧格式重新采集，空格图案正确，新的暖缓存也正确；旧偏好 ID 若失效应重新选择并核对目标，不得沿用错误布局；协议不匹配不得按错误字段解码后提交订单。

### F-12 P1 兼容性分配与缓存计数

- 方法：运行 UT-03、UT-05、UT-07、UT-08，或使用带计数器的物品接口夹具。Create 本身的单格模型不提供“槽 0 只收 B、槽 1 只收 A”的配置，不能凭普通实机画面证明这个条件。
- 预期：结果可为机器 `[B,A]`，证明未硬编码格号；同一订单/同一能力对象/同一物品键与槽位最多执行一次兼容性探测，下一轮与下一步骤复用。新订单重新探测；库存数量/容量变化仍应被每轮快照发现。

完整 `build` 包含测试与打包；26.x 还包含 `testJeiSources`。需要只复测本次 11 项 UT 时，对上述每一构建目录使用：

```bash
./gradlew -p <构建目录> --no-daemon test \
  --tests '*OrderedSlotPlanTest' \
  --tests '*RecipeGridSlotsTest' \

```

常规报告在各构建目录 `build/reports/tests/test/index.html`，JUnit XML 在 `build/test-results/test`；26.x 的补充报告在 `build/reports/tests/testJeiSources` 与 `build/test-results/testJeiSources`。执行失败必须保留日志，不能仅以 JAR 文件存在判定成功。
