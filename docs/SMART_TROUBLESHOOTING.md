# 智能排查

适用于 Minecraft 1.20.1 Forge、1.21.1 NeoForge、26.1.2 NeoForge、26.2 NeoForge、26.3 NeoForge，以及前两个版本的 BD 0.8 构建。配方诊断使用现有客户端数据；订单诊断使用服务端同步的订单状态和有界执行上下文。提交失败新增稳定错误码回传，客户端和服务端须同时更新至协议 34。

合成树上方标题栏右端的 **!** 打开排查向导。该处位于树画布之外，避开右侧目标、数量、下单按钮和材料列表。玩家先选择“root 不符”“缺少分类”“NBT/组件”“无法下单”或“制作卡住”。前三类填写对应信息后点击“开始排查”；后两类直接检查当前规划或引导进入订单排查。打开向导后仍保留原合成界面和规划接收器；返回或按 Esc 回到原树。报告为点击时的快照，准备状态变化后可再次排查，支持滚轮和翻页。修改输入后，复制旧报告和 profile 暂时禁用，重新排查后恢复。

目标框支持输入物品 ID，也支持从 JEI 拖入物品、流体及其他 BD 支持的资源样本。拖入样本保留完整 NBT/组件；留空使用当前样本，输入不同物品 ID 时只代表该物品的默认组件，报告会提醒。诊断目标可以与当前订单不同，但不会修改订单或 root。

- root 不符：输入目标样本和可选的期望配方 ID；对照当前 root 的资源身份与配方 ID，检查期望配方是否在目标资源桶中。
- 缺少分类：输入目标样本和期望 JEI 分类 ID；区分浏览器未识别分类、网络未启用类型、分类已启用但目录没有目标产物、已有候选但当前 root 来自其他分类，以及同种物品的 NBT/组件变体。诊断可以查看已采集但被网络范围过滤掉的候选；不会因此让它们参与普通规划。
- NBT/组件：输入或拖入精确目标样本，指定要对比的配方；从入口或当前 root 预填配方 ID，并列出该配方的已采集产物差异。

期望分类/配方在有入口信息时自动预填；未知的玩家意图不会由系统猜测。分类使用 `namespace:category`，配方使用 `namespace:recipe`。选择“缺少分类”后，点击期望分类输入框右侧 `v` 打开下拉列表；可按分类名称、ID 或原版炉类运行时名称搜索，点击条目填入准确分类 ID。滚轮及底部 `< >` 翻页，返回/Esc 先收起列表。手动输入仍可用；列表只在展开时读取一次浏览器元数据，加载完成后重新展开可刷新。

报告包含目标与当前 root 是否精确一致、入口及当前配方 ID、配方类型、原生或 JEI/EMI 来源、相关模组版本、网络启用范围、采集进度及本次 JEI 采集失败摘要。JEI runtime 缺失与 EMI 使用情况分别显示；网络类型未出现在浏览器分类中仅作为疑点，并排除已配置原生 fallback 的类型，不将类型别名直接判成兼容错误。

NBT/组件检查读取已物化目录中当前资源的桶。精确产物优先；同种资源只有一个非精确产物时列出差异；有多个非精确变体时报告歧义而不猜选。root 没有配方时，最多列四个现有候选及其字段差异。字段投影复用现有上限（128 叶子、32 层、8192 字符、每值 256 字符），每对最多显示十六项。截断或编码失败不能用于证明组件等价。

“复制报告”把当前报告放到剪贴板，由玩家补充期望的配方/产物、实际现象、截图及日志后反馈。操作不会自动上传或发送。I/O profile 仅展示实际匹配当前配方的配置；没有 profile 不代表不兼容。虚拟配方显示输入组，对全部使用 `ingredients` 的情况给出条件性线索，不据此断言分组错误。

当前 root 与指定的期望配方/分类及目标产物对应时，原生配方可“复制 profile”取得空模板；否则只给出反馈线索，避免为无关 root 生成模板。它有当前配方 ID 前缀、类及可用类型选择器，保留默认解析，并留空输入/输出字段。**模板不是修复规则**：需开发者查阅对应模组源码核对字段、数量和输入语义；ID 前缀也可能覆盖同前缀的其他配方，安装前必须检查。完整配置放入数据包 `data/<命名空间>/recipe_io_profiles/<名称>.json`。JEI 虚拟配方不生成代理类的 I/O 模板；漏原料、容器或工具组时，报告提示核对 `jei_input_group_profiles`。

诊断不会调用真实配方的 `assemble`、重新搜索规划路线、扫描服务端配方或修改选择/库存匹配。静态产物一致也不能证明动态执行结果、机器过滤、实际槽位或库存正确。

## 解决方案与订单排查

诊断结果先显示操作方案或“需检查”步骤，再展示证据。它不会自动改绑定、过滤、配方偏好或库存，也不把排查模板直接安装为修复规则。

- **分类未启用**：每次开始排查，向服务端查询当前菜单所属网络的可用类型和匹配绑定记录，区分无绑定记录、有记录但不可用、已启用。查询校验菜单 ID、nonce、分类和网络访问权限；输入变化或旧回包不会套用到新查询。读取当前网络的绑定索引，只核对已知端点，不扫描世界或服务端全量配方。返回最多八条记录的位置；供给器记录显示供给器位置和扫描目标 ID。
- **设备与操作方案**：从 JEI 催化剂/EMI 工作站的缓存反查该分类对应的方块，列出最多八个候选的本地化名称与物品 ID。针对第一个候选给出连接器投料面绑定、循环切换至期望类型、重新打开树验证的步骤；并提供供给器手动选择或扫描候选、材料组、实际投料、产物回收步骤。普通催化剂物品不会被推荐为可绑定机器；浏览器没提供设备时明确说明。设备建议不证明其能力、能源或槽位已满足。没有网络管理权限时提示由管理员执行。
- 当前绑定与界面打开时的范围不一致时，先提示重新打开树刷新目录，不用旧目录断言目标配方缺失。原生/代理类型已启用但没有设备记录时也不会误报未绑定。
- **无法下单**：结合当前规划结果、索引/加载状态、缺料清单、入口/服务端预览错误，区分加载未完成、缺料、无可用方案、循环、预算耗尽、快照变化及兼容问题。服务端拒绝提交后，额外回传稳定错误码，区分冷却、订单上限、原料变化、返还空间不足与交付类型不受支持。回传校验菜单 ID 和实际提交 nonce；不把旧菜单或其他提交的错误套到当前订单上。最新提交拒绝保留至下一次提交或关闭界面，不随新预览成功而丢失。
- **制作卡住**：在配方树选择此项，点击“查看订单排查”；也可直接打开合成状态，选中订单后点击“智能排查”。页面保留订单状态接收器，自动跟随状态刷新，支持滚轮、复制、手动刷新；返回或 Esc 回到原订单列表。首次尚未收到服务端状态时不作执行结论。

执行建议覆盖：机器/类型不可用、材料组未分配、供给器空间不足、网络容量不足、阻挡模式、旧产物待清空、设备解绑/更改、原料等待、端点过滤、前置步骤/设备占用、同资源输入输出限制、模拟/产物不符，以及最终交付和动态补货目标问题。对“等待产物”只列出投料、能源/加工条件、回收路径与精确组件的检查顺序，不断言缺电或机器故障。处理后通过等待原因、完成步骤和回收量是否变化来验证。

每次订单增量更新附带最多四个未完成步骤的配方 ID、类型；已存在执行等待记录时附带最多四个承接端的维度/坐标/材料组及回收量，端点文本上限 1024 字符。数据只读自已保存的执行状态，不查询机器内部或扫描世界。样本按步骤索引截取，可能没有包含实际阻塞步骤；订单只有一个汇总原因，并行步骤不能逐一套用该原因。未记录承接端也不能证明没有绑定设备。已失败订单不会因改配置自动恢复，重下前需核对已投材料和已有产物。

“无法下单”结果是点击时快照，状态变化后需重新开始排查；新的提交拒绝会标记旧报告不可复制，重新排查后恢复。订单排查结果随同步更新。未知原因保持“尚未定位”，不根据文本关键词猜测机器内部故障。

## 验收

七个构建均需完成以下游戏内检查（目前尚未完成图形验收）：

1. 最小及常用 GUI 尺寸下，标题不与 ! 重叠，报告文字不覆盖底部按钮。报告期间数量、下单和树交互不可触发；滚动仅滚报告。返回、Esc、调整窗口尺寸后，数量、root 选择、树状态及规划接收器保留。
2. 首次打开先出现问题类型，选型后才出现输入框。拖入不同 NBT 的 JEI 样本，检查没有消耗物品且样本保持完整。索引加载期间排查，结果为未完成；完成后重新排查可得到新结果。未加载 JEI 时显示 runtime 状态，EMI 可用分类仍计入分类核对。
3. 同 ID、不同 NBT/组件的目标与产物显示差异字段；root 无配方但有候选时仍能看到候选差异。一个配方多个非精确变体不得自动选择，精确变体存在时应优先通过。
4. 使用异常 JEI 布局，报告包含分类及失败数；重新加载 runtime 后清空旧失败。未知类型显示疑点而非通过，原生 fallback 类型不报缺分类。通用输入组只给线索。
5. 复制报告及模板到文本编辑器，检查配方 ID、版本和字段差异。虚拟配方禁用复制 I/O profile。模板保持空字段，不生成忽略 NBT 的规则。
6. 打开/关闭排查后，普通配方批处理、火箭严格身份与动态产物记录行为不变。
7. 当前 root 为 A，填写期望配方 B，显示具体 ID 差异。分类 X 在 JEI 中存在但网络未启用时提示启用；X 已启用但目标产物未采集时提示反馈分类布局；X 有同资源产物但组件不同则定位到组件差异。未知分类 ID 提示核对名称及浏览器状态，不当作确定的模组兼容结论。

自动回归覆盖加载状态的保守判定、精确/单变体/歧义/无产物分类、有界字段差异，以及实际目录中歧义产物的只读查询。构建与程序测试不能替代上述游戏内验收。

8. 在“无法下单”中分别验证加载中、缺料、循环、搜索超限、快照变化。服务端冷却/订单上限拒绝提交后，无需从聊天手抄错误即可重新排查；不同菜单 ID 或非最后提交 nonce 的回包不污染当前诊断。
9. 在订单列表选中订单后打开排查，制造材料组未分配、空间不足、过滤拦截、等待产物和交付空间不足；检查操作建议、配方与端点上下文。确认滚轮、返回、Esc、窗口调整、订单翻页和自动刷新不触发取消订单；初始占位订单不产生执行结论，订单消失后显示状态不可用。
10. 多条并行步骤等待时，显示有界上下文及汇总原因的范围提示，不把第一台机器当成所有步骤的阻塞设备。
