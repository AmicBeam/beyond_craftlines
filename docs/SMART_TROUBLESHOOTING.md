# 智能排查

适用于 Minecraft 1.20.1 Forge、1.21.1 NeoForge、26.1.2 NeoForge、26.2 NeoForge、26.3 NeoForge，以及前两个版本的 BD 0.8 构建。此功能使用现有客户端数据，不改变网络协议。

合成树上方标题栏右端的 **!** 打开排查向导。该处位于树画布之外，避开右侧目标、数量、下单按钮和材料列表。玩家先选择“root 不符”“缺少分类”或“NBT/组件”，再输入对应信息，点击“开始排查”。打开向导后仍保留原合成界面和规划接收器；返回或按 Esc 回到原树。报告为点击时的快照，准备状态变化后可再次排查，支持滚轮和翻页。修改输入后，复制旧报告和 profile 暂时禁用，重新排查后恢复。

目标框支持输入物品 ID，也支持从 JEI 拖入物品、流体及其他 BD 支持的资源样本。拖入样本保留完整 NBT/组件；留空使用当前样本，输入不同物品 ID 时只代表该物品的默认组件，报告会提醒。诊断目标可以与当前订单不同，但不会修改订单或 root。

- root 不符：输入目标样本和可选的期望配方 ID；对照当前 root 的资源身份与配方 ID，检查期望配方是否在目标资源桶中。
- 缺少分类：输入目标样本和期望 JEI 分类 ID；区分服务端黑名单主动屏蔽、浏览器未识别分类、网络未启用类型、分类已启用但目录没有目标产物、已有候选但当前 root 来自其他分类，以及同种物品的 NBT/组件变体。诊断可以查看已采集但被网络范围过滤掉的候选；不会因此让它们参与普通规划。
- NBT/组件：输入或拖入精确目标样本，指定要对比的配方；从入口或当前 root 预填配方 ID，并列出该配方的已采集产物差异。

期望分类/配方在有入口信息时自动预填；未知的玩家意图不会由系统猜测。分类使用 `namespace:category`，配方使用 `namespace:recipe`。

报告包含目标与当前 root 是否精确一致、入口及当前配方 ID、配方类型、原生或 JEI/EMI 来源、相关模组版本、网络启用范围、采集进度及本次 JEI 采集失败摘要。JEI runtime 缺失与 EMI 使用情况分别显示；网络类型未出现在浏览器分类中仅作为疑点，并排除已配置原生 fallback 的类型，不将类型别名直接判成兼容错误。

NBT/组件检查读取已物化目录中当前资源的桶。精确产物优先；同种资源只有一个非精确产物时列出差异；有多个非精确变体时报告歧义而不猜选。root 没有配方时，最多列四个现有候选及其字段差异。字段投影复用现有上限（128 叶子、32 层、8192 字符、每值 256 字符），每对最多显示十六项。截断或编码失败不能用于证明组件等价。

“复制报告”把当前报告放到剪贴板，由玩家补充期望的配方/产物、实际现象、截图及日志后反馈。操作不会自动上传或发送。I/O profile 仅展示实际匹配当前配方的配置；没有 profile 不代表不兼容。虚拟配方显示输入组，对全部使用 `ingredients` 的情况给出条件性线索，不据此断言分组错误。

当前 root 与指定的期望配方/分类及目标产物对应时，原生配方可“复制 profile”取得空模板；否则只给出反馈线索，避免为无关 root 生成模板。它有当前配方 ID 前缀、类及可用类型选择器，保留默认解析，并留空输入/输出字段。**模板不是修复规则**：需开发者查阅对应模组源码核对字段、数量和输入语义；ID 前缀也可能覆盖同前缀的其他配方，安装前必须检查。完整配置放入数据包 `data/<命名空间>/recipe_io_profiles/<名称>.json`。JEI 虚拟配方不生成代理类的 I/O 模板；漏原料、容器或工具组时，报告提示核对 `jei_input_group_profiles`。

诊断不会调用真实配方的 `assemble`、重新搜索规划路线、扫描服务端配方或修改选择/库存匹配。静态产物一致也不能证明动态执行结果、机器过滤、实际槽位或库存正确。

## 验收

七个构建均需完成以下游戏内检查：

1. 最小及常用 GUI 尺寸下，标题不与 ! 重叠，报告文字不覆盖底部按钮。报告期间数量、下单和树交互不可触发；滚动仅滚报告。返回、Esc、调整窗口尺寸后，数量、root 选择、树状态及规划接收器保留。
2. 首次打开先出现问题类型，选型后才出现输入框。拖入不同 NBT 的 JEI 样本，检查没有消耗物品且样本保持完整。索引加载期间排查，结果为未完成；完成后重新排查可得到新结果。未加载 JEI 时显示 runtime 状态，EMI 可用分类仍计入分类核对。
3. 同 ID、不同 NBT/组件的目标与产物显示差异字段；root 无配方但有候选时仍能看到候选差异。一个配方多个非精确变体不得自动选择，精确变体存在时应优先通过。
4. 使用异常 JEI 布局，报告包含分类及失败数；重新加载 runtime 后清空旧失败。未知类型显示疑点而非通过，原生 fallback 类型不报缺分类。通用输入组只给线索。
5. 复制报告及模板到文本编辑器，检查配方 ID、版本和字段差异。虚拟配方禁用复制 I/O profile。模板保持空字段，不生成忽略 NBT 的规则。
6. 打开/关闭排查后，普通配方批处理、火箭严格身份与动态产物记录行为不变。
7. 当前 root 为 A，填写期望配方 B，显示具体 ID 差异。分类 X 在 JEI 中存在但网络未启用时提示启用；X 已启用但目标产物未采集时提示反馈分类布局；X 有同资源产物但组件不同则定位到组件差异。未知分类 ID 提示核对名称及浏览器状态，不当作确定的模组兼容结论。

自动回归覆盖加载状态的保守判定、精确/单变体/歧义/无产物分类、有界字段差异，以及实际目录中歧义产物的只读查询。构建与程序测试不能替代上述游戏内验收。

### 分类搜索补全（2026-11-09）

五个 MC 版本及两个 BD 0.8 构建的“缺少分类”输入框复用供给器的搜索匹配规则：按完整分类 ID、ID 片段或本地化名称筛选，列表按 ID 排序，最多显示五行并可滚动。点击或使用方向键与 Enter/Tab 选中后填入完整分类 ID，而非显示名称；悬停可查看未截断的名称和 ID。Esc 先收起下拉框，点击外部或开始排查也会收起。普通配方 ID 输入框不显示分类列表。

分类加载后候选会更新，查询与分类集合未变化时复用匹配结果。输入未知 ID 仍可继续排查；主动屏蔽的类别不出现在普通候选中，但可手动输入以查看黑名单原因。编辑搜索文本或选择候选只更新诊断输入，不修改供给器配置或当前订单，也不会自动开始排查。

游戏内验收：以“熔炼”和 `create:fan_` 搜索，检查鼠标、滚轮及键盘补全；验证填入的是 UID、输入 `e` 不关闭窗口、未知 ID 可保留、切换到其他问题类型后不显示分类下拉框，并在调整 GUI 尺寸后核对边界。
