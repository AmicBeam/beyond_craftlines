# Beyond: Craftlines 人工验收文档

适用版本：Minecraft 1.21.1 / NeoForge / Beyond Dimensions 0.7.27+ / JEI 19.44.0.401+ / Beyond: Craftlines 0.1.0

本文只验收 `beyond_craftlines`。构象锚点、沙盒维度、试产报告、稳定图纸、构象执行器和图纸复制台属于独立模组 Sky Logistics: Linefold，不得出现在本轮验收内容、创造栏或 Craftlines 配方树中。

## 1. 验收范围

必须覆盖以下主体：

1. Beyond Dimensions（下称 BD）维度网络上下文中的 JEI 配方页下单入口。
2. EMI 风格递归配方树，以及类似 AE2/RS 的数量确认、阻挡模式、订单进度和取消界面。
3. 原版合成与 BD 网络熔炉的真实订单。
4. 网络联结器通过 JEI 催化剂确定性识别第三方机器的 `RecipeType`。
5. Mekanism 冶金灌注机真实绑定与生产。
6. 天穹物流供奉祭坛的 `skylogistics:sky_offering` 识别，以及通过“合成链供给器”交付需要玩家手动摆放的材料。
7. 合成链供给器的动态存储、无 GUI、拒绝管道输入、玩家/管道提取和网络绑定语义。
8. 订单持久化、同网络串行、跨网络并行、阻挡、缺料、取消和权限检查。

## 2. 测试环境

### 2.1 模组组合

基础组：

- NeoForge 1.21.1。
- Beyond Dimensions 0.7.27 或更高版本。
- JEI 19.44.0.401 或更高版本。
- Beyond: Craftlines 当前待验收 JAR。

完整组额外安装：

- Mekanism 1.21.1 对应版本。
- Sky Logistics 1.0.0 或更高版本，并启用其 JEI 配方类别。

### 2.2 世界与账户

1. 新建允许命令的创造模式世界。
2. 用 `beyonddimensions:net_creater`（维度网络发生器）创建一个 BD 网络，记录聊天中出现的网络 ID。
3. 确保测试玩家是该网络管理员，并把它设为玩家当前网络。
4. 准备 `beyonddimensions:net_terminal_block` 或 `beyonddimensions:net_terminal_item`，用于打开真实 `DimensionsNetMenu`。
5. 多人权限用例另准备玩家 B；B 初始不是该网络管理员。

## 3. 新物品、方块与资源

### CONTENT-01：创造栏、图标和模型

1. 打开创造物品栏，搜索“超越维度：合成链”。
2. 必须只看到以下两个内容：
   - `beyond_craftlines:network_linker`，中文名“网络联结器”。
   - `beyond_craftlines:craftline_provisioner`，中文名“合成链供给器”。
3. 网络联结器应为独立物品图标；供给器应有正确方块物品模型和放置后模型。
4. 两者都不得出现紫黑缺失材质，也不得直接复用天穹石或原版箱子整张贴图。
5. 搜索“构象锚点”“不稳定图纸”“试产报告”。本模组创造栏不得提供这些已拆分内容。

### CONTENT-02：真实合成配方

网络联结器：

```text
空            铁锭                 空
红石粉        破碎的时空结晶       红石粉
空            铁锭                 空
```

合成链供给器：

```text
铁锭          漏斗                 铁锭
红石粉        破碎的时空结晶       红石粉
铁锭          箱子                 铁锭
```

其中“破碎的时空结晶”为 `beyonddimensions:shattered_space_time_crystallization`。在普通合成台实际摆放，必须分别得到 1 个网络联结器和 1 个合成链供给器，物品名与注册 ID 正确。

供给器配方不得消耗网络联结器。两件内容采用 BD 自身的材料层级：破碎的时空结晶作为低阶网络核心，铁锭构成外壳，红石表达控制逻辑，漏斗和箱子表达供给与存储功能。

## 4. 依赖与启动

### BOOT-01：客户端与专用服务端

1. 用基础组启动客户端并进入世界。
2. 必须正常加载；日志不得出现客户端类在专用服务端加载、JEI 插件注册失败、BD API 链接错误或网络包注册冲突。
3. 用相同模组集合启动专用服务端并加入。
4. 打开 BD 网络终端、JEI 和 Craftlines 订单界面，均不得导致服务端崩溃。

### BOOT-02：硬依赖

分别复制实例测试：

1. 移除 JEI，启动游戏。加载器必须明确拒绝启动，并指出 `jei` 缺失；不得进入世界后再崩溃。
2. 恢复 JEI、移除 Beyond Dimensions。加载器必须明确指出 `beyonddimensions` 缺失。
3. 恢复基础组、不安装 Sky Logistics 和 Mekanism。Craftlines 必须仍可进入世界并完成原版用例。

## 5. JEI 下单入口

### JEI-ENTRY-01：入口只出现在正确上下文

1. 关闭所有容器，只打开普通 JEI 配方查询页，例如查看 `minecraft:piston` 的配方。
2. 配方页上不得出现 Craftlines 网络联结器图标按钮。
3. 打开普通箱子，再查看同一 JEI 配方。
4. 仍不得出现 Craftlines 按钮。
5. 关闭箱子，打开绑定当前网络的 BD 网络终端，使当前菜单为 BD 维度网络界面。
6. 在不离开 BD 界面的情况下，通过 JEI 查看活塞配方。
7. JEI 配方卡片旁必须出现一个使用“网络联结器”图标的额外按钮；按钮应与 JEI 原生配方按钮同一视觉层级，不得出现在 BD 界面右上角。
8. 悬停按钮，必须显示“打开 Craftlines 配方树”。
9. 切换 JEI 的不同配方卡片，每张有物品产物的配方都应获得自己的按钮；无可下单物品输出的页面不得出现可用按钮。

### JEI-ENTRY-02：从 JEI 打开订单页面

1. 在 BD 网络界面内查看 `minecraft:piston` 配方。
2. 点击网络联结器图标按钮。
3. 必须关闭 JEI 配方覆盖层并打开标题为“制造订单”的 Craftlines 页面。
4. 页面右侧目标必须预选“活塞”，ID 为 `minecraft:piston`，数量初始值为 1。
5. 按 Esc 返回后，玩家仍应处于正常世界状态；不得出现容器 ID 不同步或物品槽错位。

### JEI-ENTRY-03：BD 网络物品中键

1. 在 BD 网络库存中准备 1 个 `minecraft:piston`，或让该物品以可查询的网络条目出现。
2. 鼠标移到该条目上按中键。
3. 必须进入以 `minecraft:piston` 为目标的 Craftlines 配方树/下单页面。
4. 不得绑定全局快捷键；离开 BD 网络界面后，对普通背包物品按中键不得打开 Craftlines。

若中键没有任何响应，记录为 JEI/BD 交互未完成，不得用 JEI 配方侧按钮代替本用例判通过。

## 6. 配方树与订单 GUI

### GUI-01：布局与自适应

1. 在 1920×1080 GUI 比例 2、1280×720 GUI 比例 3，以及最窄可用窗口各打开一次活塞订单页。
2. 必须看到三栏：左侧可下单产物列表、中间深色配方树画布、右侧目标数量和订单状态。
3. 页面应随窗口在约 300～620 像素宽、236～360 像素高范围内自适应；按钮不得越界或互相遮挡。
4. 左侧搜索“piston”与“活塞”都应筛出活塞。
5. 右侧必须显示当前选中产物的“网络已有：<数量>”；切换左侧产物时该数字应从服务端刷新，不能沿用上一个物品的数量。
6. 数量框表示“本次要额外制作的数量”，不是期望库存总量；只接受数字，`+1`、`+64`、`÷2` 必须正确修改数量，最小值为 1。

### GUI-02：EMI 风格树操作

1. 选择活塞。
2. 中间画布根节点必须显示活塞，子节点显示 3 木板、4 圆石、1 铁锭、1 红石对应的真实材料分支。
3. 有下级配方的材料继续向右展开，节点间必须有清晰的蓝/青连线；叶子、普通节点和根节点应有可区分的边框色。
4. 鼠标悬停任一节点，必须显示该真实物品 tooltip。
5. 在画布内按住左键或中键拖动，整棵树必须平移，左右列表不能跟着漂移。
6. 在画布内滚轮缩放，右下角百分比必须在 55%～175% 间变化，并以鼠标附近为缩放锚点。
7. 循环配方不得导致无限递归、客户端卡死或堆栈溢出；单棵树最多展示实现限制内的节点。

### GUI-03：订单状态与取消

1. 点击“阻挡 关”，按钮必须切换为“阻挡 开”，tooltip 说明目标机器含本配方输入时暂停发送。
2. 点击“下单”后，聊天必须显示“制造订单已加入队列：<UUID>”。
3. 右侧订单状态应在约 2 秒内刷新，显示目标、请求数量、状态和步骤进度；阻挡订单带 `[B]` 标记。
4. 活动订单存在时“取消”按钮可用；点击后该订单必须变为 `CANCELLED`，不能继续产出。
5. 已经从网络扣除但尚未送达机器的材料必须退回；已经进入真实外部机器且无法安全抽回的情况必须给出明确错误或人工处置说明，不得伪装为完全退款。

## 7. 原版案例

### VAN-CRAFT-01：活塞递归合成

真实目标：`minecraft:piston` ×1。

在 BD 网络放入：

- `minecraft:oak_planks` ×3。
- `minecraft:cobblestone` ×4。
- `minecraft:iron_ingot` ×1。
- `minecraft:redstone` ×1。

步骤：

1. 记录上述四种材料和活塞的网络数量。
2. 在 BD 网络界面通过 JEI 活塞配方按钮进入 Craftlines。
3. 确认树根为活塞、数量为 1、阻挡关闭，点击“下单”。
4. 必须出现订单 UUID；状态依次进入 `QUEUED/RUNNING`，随后为 `COMPLETE`。
5. 网络中必须准确扣除 3 橡木木板、4 圆石、1 铁锭、1 红石，增加 1 活塞。
6. 不得把合成结果放入玩家背包或掉在地上；产物和配方返还物应直接进入提交订单的 BD 网络。

### VAN-CRAFT-02：库存优先与批次数量

1. 在网络预放 1 活塞和制造另 3 活塞所需的材料。
2. 下单 `minecraft:piston` ×3。
3. 订单页必须显示“网络已有：1”，数量框仍为本次制作数量 3。
4. 服务端不得用已有的 1 活塞抵扣订单，必须额外执行 3 次配方并扣除 3 次材料。
5. 完成后网络应有 4 活塞，即原有 1 个加本次制作 3 个。

### VAN-CRAFT-03：普通合成树节点间隔与无限堆叠批量

1. 保持服务端配置 `crafting.virtualCraftingNodeIntervalTicks = 20`，重启世界使配置生效。
2. 选择 `minecraft:lever` ×128；网络准备 64 橡木木板和 128 圆石，不预放木棍或拉杆。
3. 配方树必须至少包含“木棍”和“拉杆”两个普通合成节点；下单并记录服务端游戏时间。
4. 木棍节点必须按原配方逐次模拟并累计产生供订单使用的 128 木棍；拆分依据是配方次数而不是 64 堆叠上限。
5. 拉杆节点不得与木棍节点在同一 tick 执行，两次普通模拟合成的游戏时间必须至少相差 20 tick。
6. 最终网络增加 128 拉杆且中间木棍正确归零，订单为 `COMPLETE`；不得额外吞料或复制物品。
7. 把配置临时改为 `40` 并重启后重复小批量测试，两个普通合成节点必须至少间隔 40 tick，证明间隔来自服务端配置而非硬编码。

### VAN-FURNACE-01：BD 网络熔炉烧制玻璃

真实设备与物品：

- `beyonddimensions:net_furnace_block`（网络熔炉）。
- `minecraft:sand` ×1。
- `minecraft:glass` ×1。
- `minecraft:coal` 或网络熔炉支持的真实燃料。

步骤：

1. 作为网络管理员放置网络熔炉。放置时必须显示 BD 的“方块已绑定网络 <ID>”消息。
2. 打开网络熔炉，预放至少可完成一次烧炼的燃料；清空输入与输出槽。
3. 将“收入维度网络”设为开启；网络中放 1 沙子，不放玻璃。
4. 手持网络联结器普通右击该网络熔炉。
5. 必须拒绝并显示“BD 网络熔炉、网络高炉和网络烟熏炉已有原生能力，不允许重复绑定。”；不得绘制第三方绑定边框。
6. 打开 BD 网络终端，通过 JEI 的玻璃烧炼页进入 Craftlines，下单 1 玻璃。
7. 订单状态必须显示网络熔炉已保留/正在准备输入；沙子进入网络熔炉真实输入槽，燃料点火，烧炼进度按原版时间推进。
8. 完成后玻璃必须进入同一 BD 网络，订单变为 `COMPLETE`。
9. 再关闭网络熔炉“收入维度网络”，重复一次。Craftlines 必须能从机器真实输出槽收取玻璃并放回网络，同样完成订单。

## 8. Mekanism 冶金灌注机案例

真实配方：`minecraft:iron_ingot` + 10 mB 红石灌注类型 → `mekanism:alloy_infused`（富集合金）。

必须保持通用实现：Craftlines 源码和配置中不得写死 `mekanism:metallurgic_infuser` 或 `mekanism:metallurgic_infusing` 分支；机器关系来自 JEI 催化剂，服务端只接受同 ID、已加载的 `RecipeType`。

### MEK-BIND-01：确定性 RecipeType 识别

1. 放置 `mekanism:metallurgic_infuser` 并供电。
2. 确保测试玩家当前管理的 BD 网络就是本轮网络。
3. 手持 `beyond_craftlines:network_linker`，对世界中的冶金灌注机方块普通右击。
4. 本次右击必须被网络联结器消费，**不得打开冶金灌注机自身 GUI**。
5. 必须显示“第三方机器已直接并入 Beyond Dimensions 网络，可执行配方族：mekanism:metallurgic_infusing。”
6. 机器外轮廓必须出现三层黑—深蓝—亮青绑定边框；96 格外不应渲染。
7. 重进世界后边框仍应恢复，证明绑定记录已同步和持久化。
8. 潜行右击机器，必须显示“设备已解绑。”，边框立即消失，并且同样不得打开机器 GUI。
9. 再次绑定，为生产用例准备。

失败判据：普通右击或潜行右击联结器时打开了冶金灌注机 GUI；通过扫描类名、方块 ID 猜类型；把方块 ID `mekanism:metallurgic_infuser` 当配方类型；客户端上报不存在的 category 后服务端仍接受。

### MEK-RUN-01：真实机器生产

1. 在冶金灌注机侧面配置中开放真实物品输入、额外输入和输出能力，并清空产物槽。
2. 给机器加入恰好 10 mB 红石灌注类型。可在 GUI 中放入 1 红石完成真实转换；这是当前通用物品能力用例的化学前置条件。
3. BD 网络只放 1 `minecraft:iron_ingot`，记录富集合金数量为 0。
4. 在 BD 网络终端通过 JEI 的富集合金配方页打开 Craftlines。
5. 配方树必须显示产物 `mekanism:alloy_infused` 和 Craftlines 通用资源模型已识别的铁锭物品输入；不得显示、扣取或诊断未被通用适配器建模的 Mekanism Chemical，也不得出现“红石灌注”等第三方专用提示。
6. 下单 1 富集合金。
7. 必须看到铁锭从 BD 网络减少并进入冶金灌注机真实输入槽；机器消耗 10 mB 红石灌注并推进真实进度。
8. 产出 1 富集合金后，Craftlines 必须从可抽取输出面收走并插入原 BD 网络；订单变为 `COMPLETE`。
9. 清空机器输入槽，确保机器至少有 20 mB 红石灌注，并向 BD 网络补入 2 铁锭。在订单页开启“阻挡 开”，将“制作数量”设为 2 后下单；必须先只从 BD 网络向机器投入 1 铁锭。第一枚富集合金完成并回收到网络前，不得投入第二枚铁锭；第一批完成后才自动投入第二枚并最终得到 2 枚富集合金。

说明：本模式保持 AE2 Pattern Provider 的语义。除上述“每次只推送一批”外，如果目标机器事先已有任一已登记配方的输入，首批推送也会被阻止；这项兼容行为保留，但不作为本案例的主要观察方式。
10. 阻挡关闭时重复同样场景，只要机器有容量就应继续投料。

### MEK-RUN-02：未建模第三方资源的解耦边界

1. 清空冶金灌注机红石灌注槽，BD 网络放 1 铁锭和 1 红石。
2. 下单 1 富集合金。
3. Craftlines 不得把 BD 网络中的红石当作 Chemical 扣除，不得自行向灌注槽转换或输送红石灌注，也不得在 GUI 中出现“缺少/等待红石灌注”等 Mekanism 专用诊断。
4. 订单只能保持通用的“等待机器产物”状态。随后由玩家通过 Mekanism 自身机制补足机器所需 Chemical；机器开始加工并产出后，Craftlines 必须自动回收产物并完成订单。
5. 若生产代码、配置、映射表或本地化文本出现 Mekanism 方块 ID、配方类型 ID、Chemical 名称的特判，本用例失败。

## 9. 合成链供给器与天穹祭坛

本章节按供给器的目标语义验收：供给器不是自动祭坛，也不会被注册成 `sky_offering` 催化剂；它只把订单为人工设备准备好的材料暂存起来，等待玩家手动取出或由管道等外部物流抽取。

真实天穹配方使用 `skylogistics:celestial_glass_offering`：

- 主祭品：已充能 `skylogistics:eulogia_crystal` ×1。
- 供品：`minecraft:glass` ×8。
- 供品：`minecraft:glowstone_dust` ×8。
- 产物：`skylogistics:celestial_glass` ×8。
- JEI/服务端配方类型：`skylogistics:sky_offering`。

### PROV-01：放置、网络和无 GUI

1. 作为当前 BD 网络管理员放置 `beyond_craftlines:craftline_provisioner`。
2. 放置时必须自动绑定玩家当前网络，并出现 BD 的网络绑定消息。
3. 安装 Jade 并把准星指向供给器。除 BD 原生网络信息外，Craftlines 必须额外显示“承接配方：未绑定”；不得重复实现或重复显示 BD 的网络信息。
4. 空手普通右击空供给器。
5. 不得打开 GUI；必须显示“合成链供给器内有 0 类资源，网络 ID：<ID>。空手右击可取出一组物品。”
6. 空手潜行右击供给器，应走 BD 原生绑定/解绑语义；解绑后再次潜行右击可绑定当前管理员网络。

未安装 Jade 时，本用例只跳过第 3 步及第 6 步中的 Jade 显示检查；供给器和服务端仍必须正常加载，不得把 Jade 变成硬依赖。

### PROV-02：联结器选择供给器再绑定祭坛类型

1. 手持网络联结器潜行右击已绑定网络的合成链供给器。
2. 必须把该供给器设为联结器的当前材料交付目标，并给出明确消息或 tooltip；不得把供给器本身注册为配方机器，也不得给它绘制第三方机器边框。
3. 放置一套真实 `skylogistics:offering_altar` 与四个 `skylogistics:offering_table`。祭坛位于配置要求的高空并具有合法 5×5 天穹石外圈。
4. 用同一网络联结器普通右击天穹供奉祭坛。
5. 必须从 JEI 催化剂解析并显示 `skylogistics:sky_offering`，建立“该配方类型 → 当前供给器”的关系。
6. 再把准星指向供给器。Jade 必须显示“承接配方：天穹供奉”；名称必须直接采用 JEI 类别的本地化标题，不得显示 `skylogistics:sky_offering` 资源 ID。一个供给器绑定多个类别时，每个本地化类别名都必须列出。
7. 完成绑定后拆除祭坛。供给器的 Jade 信息仍必须显示“承接配方：天穹供奉”，该配方类型仍可出现在配方树并接受订单；绑定不能依赖原祭坛的位置、区块加载状态或方块是否仍然存在，也不得为作为扫描来源的祭坛保留黑蓝边框。
8. 如需解除绑定，先用网络联结器潜行右击供给器，再手持联结器右击空气。供给器记录的全部配方类型必须被清除；再次查看时 Jade 必须恢复为“承接配方：未绑定”，且不需要重新放置或扫描祭坛。

若普通右击直接把祭坛作为通用单方块自动机器，或拆除扫描时使用的祭坛会让供给器失去配方能力，本用例失败。

### SKY-ORDER-01：祭坛订单材料进入供给器

1. 重新完成 PROV-02 的关系绑定。
2. 准备一枚真实已充能尤洛伽水晶：在 Y≥200 的玩家背包或天穹供桌中等待默认约 60 秒，直到 tooltip 显示“已完成注入”。
3. BD 网络放入：已充能尤洛伽水晶 ×1、玻璃 ×8、荧石粉 ×8；天穹玻璃数量记为 0。
4. 打开 BD 网络终端，在 JEI 的“天穹供奉”类别查看 8 天穹玻璃配方。
5. JEI 配方卡片必须显示真实祭坛图形、主祭品、两组供品、T1 和 160 tick；Craftlines 网络联结器按钮同时可见。
6. 点击按钮进入订单页。配方树应显示天穹玻璃根节点和三种真实输入；已充能水晶的组件状态必须保留，不能退化为未充能水晶。
7. 数量保持 8，点击“下单”。
8. 网络必须扣除 1 已充能水晶、8 玻璃、8 荧石粉，并由订单事务写入已选供给器。
9. 供给器不打开 GUI；先空手右击取出其中一组材料。玩家应取得真实物品，状态中的资源种类数相应减少。
10. 再连接漏斗、天穹物流或其他可抽取物品的管道，把剩余材料抽入外部容器。管道必须能够从供给器取出真实物品，供给器中的种类数和数量随抽取减少，最终归零。
11. 尝试从任意物品管道向已清空的供给器插入 1 圆石。等待 10 秒后圆石必须仍在源容器或管道中，供给器内容不变；允许管道抽取不得同时放开管道输入。
12. 汇集玩家直接取出和管道抽出的全部真实材料，手动摆入祭坛和供桌。必须看到天穹供奉粒子与音效，约 160 tick 后得到 8 天穹玻璃。

关键判定：订单阶段的材料必须进入合成链供给器，不能被通用能力代码全部塞向祭坛的单个槽位；供给器也不能凭空生成网络中不存在的材料。

### SKY-ORDER-02：请求数量小于祭坛最小配方批次

1. 清空供给器，并在 BD 网络准备一份完整的 `skylogistics:celestial_glass_offering` 原料：已充能尤洛伽水晶 ×1、玻璃 ×8、荧石粉 ×8；天穹玻璃记为 0。
2. 从 JEI 的天穹玻璃祭坛配方进入订单页，把“制作数量”明确设为 `1` 后下单。
3. 数量 `1` 表示至少满足 1 个目标产物，但不得把不可拆分的祭坛配方按比例缩小。规划必须向上取整为一次完整祭坛配方。
4. BD 网络必须扣除完整一批原料：已充能尤洛伽水晶 ×1、玻璃 ×8、荧石粉 ×8；供给器必须收到同样的完整数量，不得只交付 1 玻璃或 1 荧石粉。
5. 取出材料并完成一次真实祭坛合成，必须消耗上述完整一批原料并产出 `skylogistics:celestial_glass` ×8。
6. 实际产出 8 是配方最小单位造成的合法超额产出；不得销毁其中 7 个来强行匹配订单数量 1，也不得额外执行第二次祭坛配方。
7. 若订单预览或状态同时展示“请求数量”和“本次实际批次产出”，应分别为 1 与 8，不得把请求数量悄悄改写为 8。

### PROV-03：动态类型与持久化

1. 连续提交至少三种人工配方材料，使供给器同时保存玻璃、荧石粉和另一种普通物品。
2. 供给器应动态增加资源类型，不受固定箱子槽位 GUI 限制。
3. 保存退出并重启专用服务端。
4. 重进后网络 ID、祭坛配方类型关系和供给器内各资源数量必须保持。
5. 分别用空手和管道逐组提取，物品不得复制或丢失；背包满时，空手提取的物品应安全掉落到玩家附近。

## 10. 权限、串行与故障恢复

### ORDER-01：同网络 FIFO

1. 在同一 BD 网络快速提交两个原版活塞订单。
2. 第一个订单正常执行；第二个必须显示 `PAUSED`，详情为 `waiting for network order transaction` 或等价本地化说明。
3. 第一单终止后第二单自动继续，最终数量准确。

### ORDER-02：不同网络并行

1. 玩家 A、B 分别管理两个不同 BD 网络，各准备一套活塞材料。
2. 同时下单。
3. 两单应并行推进，不得因为全服互斥让网络 B 等待网络 A。

### ORDER-03：权限

1. 玩家 B 不是玩家 A 网络管理员时，尝试用网络联结器绑定 A 网络的机器。
2. 必须显示绑定失败或无权限；不得生成边框和绑定记录。
3. B 不得取消 A 的订单，也不得解绑 A 的机器或供给器。

### ORDER-04：机器破坏与重启

1. Mek 订单进入 `RUNNING` 后破坏或替换冶金灌注机。
2. 订单必须进入 `ERROR`，详情说明机器已移除或改变；不得在原坐标凭空产物。
3. 重新绑定新机器后，新订单应可执行。
4. 订单运行期间正常重启服务端；重进后订单 UUID、网络 ID、步骤、阻挡模式和状态必须恢复，不得重复扣料或重复产出。

## 12. 当前源码审计重点

以下不是允许豁免的“已知限制”，而是执行本文时要重点观察的高风险点：

1. 当前 JEI 插件已有配方侧按钮，但 BD 网络物品中键需要 BD 提供槽位动作扩展点；中键无响应必须记失败。
2. 当前第三方自动化只枚举方块公开的物品能力。未进入通用资源模型的 Mek Chemical 由机器自身或玩家预先满足，Craftlines 不得扣取、输送或点名诊断；天穹祭坛的四个供桌也不能被误当作祭坛单槽。
3. 合成链供给器必须真正接入订单路径。仅注册方块、拒绝管道输入但从来收不到订单材料，不算实现完成。
4. 已充能尤洛伽水晶带物品组件；规划、扣取、供给器保存以及玩家/管道取出全程必须保留组件。
5. 绑定必须来自 JEI catalyst category UID 与服务端同 ID `RecipeType`，不得退回反射猜测、类名猜测或 Mek/Sky 专用硬编码。
